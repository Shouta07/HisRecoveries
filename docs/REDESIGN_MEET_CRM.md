## 0. いま、いちばん先に決めること

### 0-1. Gemini の議事録が自動で動くと、同意の仕組みが成り立たない

Workspace で Gemini の議事録が**オート作動**しているとのこと。
これは良い知らせだが、そのままだと設計が崩れる。

いま作ってある仕組みは、こうなっている。

```
両方が同意 → 文字起こしを始める
片方でも断る → 文字起こしを始めない。通話だけ行う
```

ところが自動で動くなら、**断られても議事録は作られる**。
「同意が無ければ録らない」が、守れない約束になる。

公開中のプライバシー方針にも、こう書いた。

> お客様と回答者の双方が、その通話ごとに同意された場合にのみ行います。

#### 取れる道

| | 中身 | 向き |
|---|---|---|
| **A. タシカメの会議だけ、自動を切る** | 会議ごとに議事録を止める設定にし、同意が取れたときだけ動かす | **勧める** |
| B. 「同意」の意味を変える | 議事録は常に作られる。同意は「使ってよいか」への同意にする。断られたら即削除 | 次善 |
| C. 同意を取るのをやめる | **不可**。方針に書いた以上、書き換えが要る。書き換えると「断れない」サービスになる |

**A を勧める。** 断ったのに録られている状態を作らない。
会議ごとに切れるかは Workspace の設定次第なので、**要確認**。

**B にする場合**、方針の文面を書き直す必要がある。

> 議事録は自動的に作成されます。同意されない場合、作成されたものは
> 使用せず、ただちに削除します。

これは「録らない」ではなく「使わずに消す」。意味が違うので、
そう書く。ごまかすと、あとで効いてくる。

**どちらにするか決まるまで、文字起こしの接続は進めない。**

### 0-2. 報酬 ¥800〜1,000 は、¥1,980 では成り立たない

| 報酬 | 変動費 | 残り | 粗利 |
|---|---|---|---|
| ¥500 | ¥670 | ¥1,310 | 66.2% |
| ¥700 | ¥870 | ¥1,110 | 56.1% |
| **¥800** | ¥970 | ¥1,010 | **51.0%** |
| **¥900** | ¥1,070 | ¥910 | **46.0%** |
| **¥1,000** | ¥1,170 | ¥810 | **40.9%** |

（AI処理 ¥30、決済3.6%、返金引当3%、雑費¥10 で計算）

いまのビルドは、売り物に粗利60%を課している。
入口だけ55%、お試しだけ39%の例外がある。**40〜51%は通らない。**

#### 選べるのは3つ

| | |
|---|---|
| **A. 価格を上げる** | 報酬¥900で粗利60%なら **¥2,820**。55%なら ¥2,450 |
| **B. 報酬を下げる** | ¥1,980 のままなら、60%で **¥622** まで、55%で ¥721 まで |
| **C. 下限を下げる** | 「相談」を入口商品として、下限を50%にする。報酬¥820まで払える |

**C を勧める。** 理由は、いま詰まっているのが**回答者集め**だから。

報酬¥500 と ¥800 では、声をかけたときの受けやすさが違う。
売り物が無い状態（回答者1人）で粗利を守っても、守るものが無い。

**ただし下限を下げることは、黙ってやらない。**
`marginFloor` に書いて、理由もコードに残す（お試しのときと同じやり方）。

### 0-3. 回答者が、相談者のマッチ相手だったら

ご指摘のとおり、完全には防げない。**当たったときに何も漏れないこと**を優先する。
これは §7 に書いた。

### 0-4. いま確認が要るもの

| | 誰が |
|---|---|
| Workspace で、会議ごとに Gemini 議事録を止められるか | お手元 |
| 議事録のテキストを API で取れるか（Drive API） | お手元 |
| Meet でゲスト参加を許可する設定 | お手元 |
| 入室許可を誰が押すか（ゲストは許可が要る場合がある） | 運用の決めごと |
| 報酬 ¥800 で受けてもらえるか | 確保済みの1人に |

**出会いは作らない。** マッチングもいいねも検索もしない。

売っているのは2つで、これは**1つの体験**として設計する。

```

相談しているだけで、恋愛の整理が終わる
```

利用者は管理表を書かない。**相談することが入力になる。**

## 6. Google Meet のフロー

```
決済が確定
  ↓
Calendar API で会議を作る（主催は当社アカウント）
  ↓
Meet の URL を talks に保存
  ↓
両方に、URL と「入る前の3手順」を出す
  1 ログアウトするか、シークレットウィンドウで開く
  2 表示名の欄に、出ている名前をそのまま貼る
  3 カメラを切ってから入る
  ↓
ゲストとして入る → 主催（運営）が入室を許可
  ↓
10分
  ↓
終了。議事録が Drive に落ちる
  ↓
取りに行く → §10 の匿名化へ
```

### 表示名

コードで決める（`lib/call/alias.ts`）。入る人は貼るだけ。

- 相談者 `ユーザー4821`
- 回答者 `相談員07`

人名にしない（実在の人に見える）。通し番号にしない（何人目か分かる）。
`I` と `O` は使わない（手で打つ人が `1` `0` と取り違える）。

### 入室許可は、運用の手間になる

ゲスト参加は主催者の許可が要る場合がある。
**誰が押すのかを決めないと、時間になっても誰も入れない。**

MVPでは運営が押す。予約の時間を、運営が対応できる帯に限る。

## 7. 回答者が、相談者の知り合いだったとき

完全には防げない。**当たったときに何も漏れないこと**を優先する。

### 回答者の画面に、常に出しておく

```
[ 知っている人かもしれない ]
```

### 押されたら

```
1  その場でセッションを終了
2  その回のデータを、使用停止にする（構造化もしない）
3  別の回答者へ自動で振り替える
4  料金と時間はそのまま（利用者の負担を増やさない）
5  回答者には、守秘義務が続くことを再掲
```

### 利用者に見せるのは、これだけ

```
回答者を変更します。少しお待ちください。
```

**「あなたの知人でした」とは、絶対に伝えない。**
伝えると、利用者は「誰だったのか」を考え始める。
それは相手を特定しようとする動機になり、
回答者の安全を損なう。

### 事前にできること（完全ではない）

- 同じ都道府県の回答者を優先しない（むしろ避ける）
- 相談者が「このアプリは避けたい」を1つ指定できる
- 回答者が「この年代は受けない」を設定できる

いずれも確率を下げるだけ。**当たる前提で作る。**

## 10. 個人情報の匿名化

**文字起こしを、そのまま構造化へ渡さない。**

```
議事録
  ↓
① 個人情報を見つける
  ↓
② 伏せる・抽象化する
  ↓
③ 構造化（AI）
  ↓
④ JSON
  ↓
⑤ 議事録の本文を消す
  ↓
⑥ 更新の確認へ
```

### 伏せるもの

| 見つけたもの | どうする |
|---|---|
| 実名 | `Aさん` |
| 電話番号・メール・SNSのID | 消す |
| 勤務先の固有名 | `IT業界` のように抽象化 |
| 学校名 | `大学` |
| 住所・最寄り駅 | 消す。`都内` 程度まで |
| 年齢 | `20代` の帯に |

### 順番が大事

**構造化のあとに伏せるのでは遅い。**
構造化の途中で、AIが実名を要約に含めてしまう。
伏せてから渡せば、そもそも入らない。

### 既にある部品

`lib/ask/redact.ts` に `redact()` と `mayContainName()` がある。
文字相談で使っているもの。**まずこれを通す。**
通話の文字起こしは長いので、取りこぼしは増える。前提として：

- 伏せ漏れは起きる。だから**議事録の本文を消す**（残れば漏れ続ける）
- 構造化の結果にも、もう一度 `redact()` を掛ける
- 画面に出す前に、3回目を掛ける

## 13. 回答者の業務委託運用

### 登録は一度だけ

```
本人確認 → 業務委託契約 → 守秘義務 → 禁止事項 →
報酬条件 → 振込口座
```

**毎回契約しない。** 以後は「対応できる時間を登録 → 案件が来る → 受ける」だけ。

### 人数

| | 開けるのに必要 | いま |
|---|---|---|
| 女性回答者 | 5〜10名 | 1名 |
| 男性回答者 | 5〜10名 | 0名 |

売り出しの判定は `online >= ceil(必要人数 × 1.5)`。
10分相談は1人なので、**2人いれば開く**。

**MVPは片側（男性利用者 → 女性回答者）だけで始める。**
両方同時だと、どちらも人が足りず、どちらも開かない。

### 報酬

**月末締め・翌月払い。** 都度振込にしない（振込手数料と手間が件数ぶん増える）。

¥800 とする場合、粗利 51.0%。
いまの下限（60%）を割るので、**下限を下げる判断が要る**（0-2）。

### 禁止すること（契約に入れる）

- 相談者を特定しようとすること
- 相談内容を外に出すこと
- 連絡先を交換すること
- 知っている人だと気づいたのに、続けること

## 14. 運営オペレーション

MVPで、人が手を動かすところ。

| いつ | 誰が | 何を |
|---|---|---|
| 予約が入る | 自動 | 回答者へ案件 |
| 通話の5分前 | **運営** | Meet を開いて待つ |
| 入室 | **運営** | ゲストの入室を許可 |
| 通話中 | — | 立ち会わない（聞かない） |
| 終了後 | 自動 | 議事録 → 匿名化 → 構造化 |
| 失敗したとき | **運営** | 手で足す案内を出す |
| 「知っている人」 | 自動＋**運営** | 交代の手配 |
| 月末 | **運営** | 報酬の集計と振込 |

**運営が張り付く時間帯に、予約枠を限る。** 24時間は受けない。

### 立ち会わない

通話には入らない。入ると、話す内容が変わる。
（議事録は残るので、問題が起きたときは後から見られる）

```
返金引当 3.0%     ¥59
AI（文字起こし＋匿名化＋構造化）  ¥30
雑費             ¥10
────────────────
残り            ¥1,010
```

### 無料プランの原価

相談がゼロなら、報酬もAI費も発生しない。**¥0。**
増えるのはDBの行だけ（Supabaseの無料枠を超えたら従量）。

ただし **Workspace の月額は固定費**として乗る。
件数が少ないうちは、1件あたりに重くのしかかる。

### 損益分岐（ざっくり）

固定費を月 ¥20,000（Workspace＋Vercel＋Supabase）とすると、
報酬¥800・残り¥1,010 なら **月20件**で固定費を回収。
