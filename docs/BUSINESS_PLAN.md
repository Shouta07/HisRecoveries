## 0. この計画の前提

- 数値の財務予測は、まだ一次データが無いため本書では**断定しない**。収益の「構造」と
  前提・仮説として記述し、フェーズが進むごとに実データで埋める。
- フェーズの**順序が最重要**。価値の源泉（原体験 × 編集）で権威と一次データを先に作り、
  その後にパートナー・商品で収益化する。順序を逆にすると「紹介手数料の比較サイト」に
  堕ち、価値が空洞化する。

## 1. ワンページ・ピッチ（要約）

**男性の回復体験をプロデュースするブランド。** Male Conditioning — Recover Your Presence.

- **課題**: 男性は人に言えない悩み（汗・におい／ニキビ跡／薄毛／体毛／顔の印象／自意識）を
  **ひとりで検索している。** 世界共通の課題で、日本は沈黙が一段深い。中立に理解を渡す場所が無い。
- **解**: 症状ではなく「人に見られている感覚＝自意識」を扱うメディア＋体験ブランド。
  Recovery Check（無料）／原因を読む（なぜ起こるか）／Recoveries Letter（¥500/月）。
- **なぜ今**: メンズ美容市場の拡大、男性の自己受容への関心上昇、**AI検索（GEO）への移行**で
  「出典付きの一次情報・原因解説」を持つ媒体が引用される側に回る。
- **堀**: 原体験 × 編集 × 一次データ × **中立性**（認証で手数料を取らない＝壊れない構造）。
- **モデル**: 購読／体験パッケージ／認証＋バッジ（ミシュラン型）／顧客教育SaaS／
  パートナー向けシステム／Recovery Data／共同商品。
- **現在地（正直）**: Phase 0。サイト稼働中（日英）、SEO/GEO 基盤完了。
  最初の一次データ（Check 100件・改善事例10件）を収集中。**まだ売っていない（意図的）。**
- **求めるもの**: 投資家＝一次データ蓄積と体制立ち上げの資金・知見（規模/使途は財務モデル別添）。
  パートナー＝5原則を満たす認証先（紹介手数料は取らない）。
- **ミッション**: 世の中に、自信にあふれた男性を増やし続ける。

## 2. ブランド定義

- **ミッション**: 世の中に、自信にあふれた男性を増やし続ける。
- **一行定義**: 男性の回復体験をプロデュースするブランド。
- **本質**: 扱うのは症状ではなく、その奥にある「人に見られている感覚＝男性の自意識」。
- **声**: 一人称・過去形。励まさず、煽らず、売りつけない。半歩先を歩いた当事者として。

## 3. 課題（なぜ存在するか）

- 男性は、人に言えない悩みを、ひとりで検索している。相談先がなく、沈黙が長い。
- **世界共通の課題**でありながら、日本では「弱音を見せにくい」規範が重なり、沈黙が一段深い。
- 既存の選択肢は「商品を売る美容サイト」か「強引営業のクリニック」に偏り、
  **中立に理解を渡す場所が無い**。

## 4. 独自の価値と堀（Moat）

1. **原体験** — 運営者が当事者として通過した時間。模倣できない信頼の源。
2. **編集** — 中立・非商業の判断と声。理解を翻訳し、相手を保証できる権威。
3. **一次データ** — Recovery Check と改善事例から蓄積する「誰が何に悩むか」の一次情報。
4. **中立性** — 紹介手数料・広告費を取らないこと。**巻き込んでも価値が壊れないための
   構造的防御**。編集が、認証する相手から独立していられる限りにおいてのみ成立する。

> 価値の源泉 = 原体験 × 編集 → 信頼 + 一次データ → パートナー（還元・収益化）。
> パートナーは中心だが、核ではない。順序が崩れると堀が消える。

## 5. プロダクト / サービス（現在 → 将来）

### 現在（無料中心・データ収集フェーズ）
- **Recovery Check（無料）** — 30問の自己観察に編集者が手紙で応える。一次データの入口。
- **Recovery Stories（無料）** — 当事者の改善事例アーカイブ（投稿制）。
- **Recoveries Letter（¥500/月・Substack）** — 私的な思いの発信と継続課金。

### 将来（収益化フェーズ）
- **体験パッケージ**（High/Low、§8）
- **Recovery Certified Network** — 認証 + バッジ契約（§7）
- **Recovery Path（理解→行動の SaaS）** — 顧客教育プロダクト（§9）
- **パートナー向けシステム開発** — 現場の一次情報を貯める基盤（§10）
- **共同商品** — 提携パートナーとのプロダクト・ローンチ
- **Recovery Data** — 匿名集計の知見提供（B2B）

## 6. 収益モデル（構造）

| 収益源 | 種別 | 立ち上がり |
|---|---|---|
| Recoveries Letter（購読） | toC・継続 | フェーズ0〜 |
| 体験パッケージ（High/Low） | toC・単発+継続 | フェーズ2 |
| 認証 + バッジ年会費 | toB・継続 | フェーズ1〜2 |
| Recovery Path（顧客教育 SaaS） | toB（ホワイトラベル）+ toC | フェーズ3 |
| パートナー向けシステム開発・運用 | toB・受託+SaaS | フェーズ3 |
| 共同商品（レベニューシェア） | toB2C | フェーズ2〜3 |
| Recovery Data（知見提供） | toB | フェーズ3〜 |

**原則**: 認証そのものでは紹介手数料・広告費を取らない（中立性の維持）。
収益はバッジ年会費・SaaS・システム・体験・商品・データから得る。認証の判断と収益源を分離する。

## 7. パートナー戦略 — 認証とバッジ（ミシュラン・モデル）

- **認証**: 5原則（顧客理解／強引営業の禁止／改善データ提供／顧客教育／長期伴走）+
  覆面顧客審査 + 年次更新 + 剥奪事例の公開。
- **バッジ契約**: 認証店は「Recovery Certified」バッジを掲示。ミシュランのように
  **第三者の中立評価が価値を持つ**構造。星の重みは、剥奪の厳しさと公開性が担保する。
- **価値の方向**: 認証は「お金で買えない」。だからこそ、認証された側の集客・信頼に効く。
- **収益**: 認証は無料/低額に保ち、**バッジ年会費・システム・共同商品**で収益化。
  認証の判断と収益を切り離すことで中立を守る。

## 8. 体験パッケージ（High-end / Low-end）

「医療的解決 × サロン通院 × デジタルデトックス」など複数手段を**掛け合わせ**、
単発処置で終わらせず、回復体験としてプロデュースする。

- **Low-end**: デジタル中心。Recovery Check + Letter + セルフケアの設計 + 認証店への
  （手数料を取らない）橋渡し。低価格・高到達。
- **High-end**: 伴走型。医療・サロン・生活設計・デジタルデトックスを組み合わせた
  数ヶ月〜年単位のプログラム。少人数・高単価。
- **設計思想**: 売るのは処置ではなく「整っていく時間」。各手段は認証パートナーが提供し、
  His Recoveries は編集（設計・翻訳・伴走）を担う。

> ⚠️ コンプライアンス必須: 医療を含むパッケージは、医療広告規制・医師法・あはき法・
> 景表法・特商法の確認が前提。医療行為はパートナー（医療機関）が主体で提供し、
> His Recoveries は医療行為・診断・受診勧奨を行わない。設計前に専門家レビューを通すこと。

## 9. 製品: Recovery Path（理解→行動の SaaS）

> 仮称: Recovery Path（toC）／ Recovery Path for Partners（toB ホワイトラベル）。
> 位置づけ: Phase 3〜4 の製品。**いまは作らない**（順序は §9.5）。

### 9.1 一行
ゲーミフィケーションと図解とシステムで、顧客が悩みを**本質（なぜ起こるか）から理解し、
行動を改善できる**ようにする教育プロダクト。toB（パートナーの顧客教育）にも toC にも展開。

### 9.2 なぜ作るのか
- **堀の製品化**: 「感情 → 原因 → 自己観察 → 行動 → 可視化」を1本の使われ続ける体験に束ねる。
  編集の権威が「読み物」から「ツール」になる。
- **データの自動収集**: 行動と変化の追跡そのものが**縦断的な改善データ**を生む（堀を太らせる）。
- **認証の実体化**: 第4原則「顧客教育」の実装。認証パートナーが院内で使う教育ツールになる。

### 9.3 構成（4レイヤー）
1. **理解** — 「なぜ起こるのか」をインタラクティブな図解で（メカニズムの可視化）。
2. **自己観察** — Recovery Check を起点に、自分の状態を地図/ダッシュボードとして可視化。
3. **行動** — 小さな半歩を、緩やかに記録・伴走。
4. **可視化** — 自分の変化を時間軸で見る。継続動機であり、改善データの源。

### 9.4 二つの市場
- **toB（B2B2C・最有力の楔）**: 認証パートナーの顧客教育ツールとしてホワイトラベル提供。
  「強引営業せず顧客を教育したい」を解決し、パートナー側の一次データが貯まる。
  収益＝SaaS 月額（席数/店舗数）＋導入・カスタム開発。
- **toC**: フリーミアム/サブスク。Letter・体験パッケージと束ねる。

### 9.5 「静かなゲーミフィケーション」設計原則（ブランド防御）
- 採る: 状態が**地図として埋まる**可視化／途切れても罰しない緩やかな継続／理解が深まる操作／
  内省を促す静かな問い。
- 採らない: ポイント争い・ランキング・連続記録の脅し・恥を煽るバッジ・プッシュ通知。
- 原則: **「見える進捗」は提供する。「感じる圧力」は提供しない。**

### 9.6 ビルド順序
- **いまは作らない。** Phase 0（一次データ100件）を逸らさない。
- まず手動・軽量でループを検証 → 効くと分かった教育・行動だけを Phase 3 で systematize。
- SaaS は蓄積した一次理解の**上に**建てる（堀が先、製品が後）。

### 9.7 規制・倫理（必須ゲート）
- **薬機法・医療機器**: 診断・治療・健康効果の断定を謳うと規制に触れる。本製品は
  「教育・自己理解の支援」に限定し、診断・受診勧奨をしない。設計前に専門家レビュー。
- **データ倫理**: 縦断データは堀であると同時に最も繊細な情報。匿名化徹底、PII を出さない。

## 10. データ戦略 — 貯めて、還す

```
現場・サイトで一次情報を貯める（Check / Stories / パートナーの改善データ）
        ↓ 編集が匿名化・構造化・意味づけ（学ぶ）
知見が生まれる（誰が何に悩み、何が効いたか）
        ↓ 還元
パートナーの現場改善・共同商品・体験パッケージ・Recovery Path・Recovery Data
        ↓
より良い回復体験 → さらにデータが貯まる（ループ）
```

- **パートナー向けシステム開発**を受託し、現場の顧客理解・改善データが自然に貯まる基盤を作る
  （バイタリティデザインの toB AI・DXシステム開発の本業と直結）。
- 貯まったデータは匿名で **Recovery Data** として還元し、商品・パッケージ・認証基準の
  改善に再投資する。これが「実践→集まる→学ぶ→還元」ループの実体。

## 11. 海外展開

- **方針**: 実証は日本、設計は世界。日本で型（Check→理解→改善事例→認証→体験）を作り横展開。
- **先行収集**: 海外の事例・研究も先んじて集め（各原因ページの「日本と海外」比較は布石）、
  海外パートナーを巻き込む素地を作る。
- **国境を越えるもの**: 症状のメカニズム（普遍）、自意識のテーマ（普遍）、編集の型（移植可能）。
- **現地化を要するもの**: 言語、医療・広告規制、文化的な「清潔感」の基準、決済。
- **基盤は実装済み**: `/en`・hreflang・ロケール対応のコンテンツ層。フル i18n は需要が立ってから。

## 12. フェーズ・ロードマップ

- **Phase 0 — 発信と収集（現在）**: 日本で発信、Check を回す。ゲート＝Check 100件 / 改善事例
  10件 / Letter 立ち上げ。やらない＝商品を増やす・パートナーを急いで巻き込む。
- **Phase 1 — 日本のパートナーを巻き込む**: 一次理解を背負って最初の数院・数名を認証。バッジ開始。
- **Phase 2 — 体験パッケージ & 共同商品**: High/Low を少数検証、共同商品ローンチ（コンプラ後）。
- **Phase 3 — システム & データ・ループ**: Recovery Path 投入、パートナー・システム受託、
  Recovery Data 提供。ループを仕組み化。
- **Phase 4 — 海外**: 海外事例・パートナー、英語圏、現地コンプラ・現地認証。

## 13. 5年計画（Y1–Y5）

期間: Y1 = 2026 下期〜2027、以降1年刻み（Y5 = 2030）。数値は**目標（仮説）**。
**ゲート制**: 前年の中核ゲート未達なら翌年の収益化に進まない。

| 年 | テーマ | 一行で |
|---|---|---|
| Y1 | 発信と収集 | 日本で信頼と一次データを作る（売らない） |
| Y2 | 認証の確立 | 一次理解を背負って日本パートナーを認証する |
| Y3 | 体験と商品 | 体験パッケージと共同商品で収益を立ち上げる |
| Y4 | システムとループ | 現場システムとデータ還元で仕組みでスケールする |
| Y5 | 世界へ | 海外の事例とパートナーを巻き込み、カテゴリを定義する |

- **Y1 発信と収集**（Phase 0→早期1）: 発信＋Check 運用＋改善事例ループ。
  ゲート＝**Check 100件 / 改善事例 10件 / Letter 立ち上げ**。収益ほぼゼロ（投資期）。編集1人。
- **Y2 認証の確立**（Phase 1→早期2）: 最初の5〜10を認証、バッジ開始、Recovery Data 内部版、
  Low-end 最小検証。ゲート＝**認証維持率が健全／信頼送客が機能**。
- **Y3 体験と商品**（Phase 2→3入口）: High/Low 本格運用（医療×サロン×デジタルデトックス、
  法務レビュー前提）、共同商品ローンチ、ネットワーク拡張。ゲート＝**High-end 継続率／商品の再現性**。
- **Y4 システムとループ**（Phase 3）: **Recovery Path 投入**（toB→toC）、パートナー・システム
  受託/SaaS、Recovery Data を B2B 提供、ループ定常運用、海外準備。ゲート＝**ループが収益と改善を
  両立／海外の型が見える**。
- **Y5 世界へ**（Phase 4）: 英語圏展開、フル i18n、現地認証、海外パートナー連携、
  「Male Conditioning」のカテゴリ定着。ゲート＝**海外で認証/体験/データが回り始める**。

収益の立ち上がり（質的・金額は実データでモデリング）:
```
Y1 |■            Letter のみ（投資期）
Y2 |■■■          + バッジ + Low-end
Y3 |■■■■■■       + 体験パッケージ + 共同商品
Y4 |■■■■■■■■■    + Recovery Path + システム + Recovery Data
Y5 |■■■■■■■■■■■  + 海外初期収益
```

## 14. KPI（北極星と先行指標）

- **北極星**: 「自信を取り戻した」と言える男性の数（回復体験の完了・継続）。
- **先行指標**:
  - Phase 0: Check 完了数 / 完了率 / 改善事例数 / Letter 継続率 / 流入元別CV（UTM）
  - Phase 1+: 認証店数 / 認証維持率（剥奪率）/ バッジ年会費 / 信頼での送客の質
  - Phase 2+: パッケージ単価・継続率 / 共同商品売上 / パートナーNPS
  - Phase 3+: Recovery Path 導入数・継続 / システム契約 / Recovery Data 契約

## 15. リスクと防御

| リスク | 防御 |
|---|---|
| 中立性の毀損（パートナー収益への依存） | 認証と収益源を分離。紹介手数料ゼロ。剥奪事例の公開 |
| 医療・広告の法規制（含 薬機法） | 医療はパートナー主体。免責明記。設計前に専門家レビュー |
| 編集（属人）への依存 | 声と基準を文書化（本書・llms.txt・編集ガイド）。段階的に編集チーム化 |
| スケールと編集品質の両立 | 数より質。認証・パッケージ・SaaS は少数精鋭から |
| データの倫理（男性の沈黙） | 匿名化徹底。PII をダッシュボードに出さない。当事者の尊厳を最優先 |
| 順序の誘惑（早すぎる収益化） | フェーズ・ゲートを守る。Phase 0 の目標未達では次に進まない |
| ゲーミフィケーションのブランド毀損 | 「静かなゲーミフィケーション」原則（§9.5）を厳守 |

## 16. 体制

- **運営**: バイタリティデザイン合同会社（「人と事業の活力を設計する会社」）。
- **現在**: 編集（運営者）1人 + AI・DX システム開発の本業。
- **将来**: 編集チーム、覆面審査員、パートナー開発、システム開発体制へ段階拡張。
- **資産の置き場所**: ブランド（His Recoveries）は中立の編集体。収益事業（認証運用・
  システム・パッケージ・SaaS）は会社側。編集の独立を構造で守る。

## 17. 次の12ヶ月（具体）

1. **発信を回す**: Threads（自動化 + 編集）で痛みを言語化 → Check へ。
2. **100件 + 10事例**を集める（Phase 0 ゲート）。
3. データを読み、**最初の認証基準を実データで調整**。
4. 最初の**数店を認証 + バッジ契約**（Phase 1）。
5. High/Low パッケージの**最小検証**（コンプラ確認後）。
6. 海外事例の収集を継続し、英語コアを育てる。
7. Recovery Path の**最小検証**を設計（コードを増やさず、何でループを測るか）。

## 18. 全期間で守る原則（崩すと価値が消える）

1. **順序**: 権威・一次データ → パートナー → 収益化 → 海外。早すぎる収益化をしない。
2. **中立**: 認証で紹介手数料・広告費を取らない。認証と収益源を分離する。
3. **質 > 数**: 認証・パッケージ・パートナー・SaaS は少数精鋭から。剥奪を恐れない。
4. **編集の独立**: 認証する相手から、編集は構造的に独立し続ける。
5. **当事者の尊厳**: 匿名化徹底、PII を出さない、沈黙を尊重する。
6. **法務ゲート**: 医療を含む設計は専門家レビュー後にのみ進める。
7. **静かなゲーミフィケーション**: 見える進捗は提供する。感じる圧力は提供しない。
