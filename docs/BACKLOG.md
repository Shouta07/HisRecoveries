# バックログ

優先度は P0 → P5。P0 は「壊れている・危ない」。P5 は見た目。
上から順にやる。増えたらここに足す。

書き方：`- [ ] P1 見出し — Impact / Effort / 依存`

---

## P0 データが壊れる・お金が合わない

- [x] **チケットの二重消費** — 残高を読んでから書く2段構えで、同時に来ると
      5回パスで6回使えた。`spend_pass`（Postgres関数、行ロック）に移した。
      同じ相談が二度使うのも、関数の中で止めている。
- [x] **チケットの返金・取り消しの口が無い** — `refund_pass`（Postgres関数）を作り、
      `pass_uses` に種別（consume / refund / bonus / admin）と符号を足した。
      消さずに打ち消す行を足すので、何が起きたか残る。二度返さない。
      足りなかったときの画面（Shortfall）も、お金ではなく回数で返すようにした。
- [ ] P0 **パスの鍵が端末から消えると、残りが取り戻せない**
      履歴を消した・端末を変えた・私用ウィンドウ。どれでも消える。
      メールに鍵を送る仕組みが要る。いまは失うと戻せない。
      Impact 大 / Effort 中 / 依存：メール送信基盤

## P1 取引が成立しない

- [ ] P1 **画像・LINEスクショを受け取れない**
      「このLINE送っていい？」がいちばん多い入口なのに、
      いまは文字で書き写してもらっている。
      Supabase Storage（private bucket ＋ 署名付きURL）が要る。
      これが入ると `style`（見た目・服装）カテゴリも開ける。
      Impact 大 / Effort 大 / 依存：SUPABASE_URL, SERVICE_KEY
- [ ] P1 **AIの口がまだ無い**
      相談の整理も、成果物の整形も、いまは無し。
      女性の回答だけで成果物が成立する形にはしてある。
      足すなら `lib/ai/` を1つ作り、失敗してもフローを止めない作りにする。
      Impact 中 / Effort 中 / 依存：LLMの鍵（有料）
- [x] **相手ごとのケース** — `relationship_cases` を作り、相談をぶら下げた。
- [x] **ケースのタイムライン** — マイページに出した。
      「前回の続きから確かめる」で、そのケースにぶら下げて相談できる。

## P2 買われない・使われない

- [ ] P2 相談の入力が一度に全部出る（Progressive Disclosure になっていない）
- [ ] P2 記事のCTAが、いまも一部トップへ向いている（相談入力へ直結させる）
- [ ] P2 「5回使える」が、値段の近くでしか言えていない

## P3 運営が重い・粗利が見えない

- [x] **案件単位の粗利** — `consultation_economics`（ビュー）を作った。
      まとめ売りは「買った金額 ÷ 買った回数 × 使った回数」で売価を割り当てる。
      使われなかった回数を利益にしない（全部使われても成立する数字にする）。
- [ ] P3 **粗利のビューを管理画面に出していない**
      ビューはできたが、`/admin` に表が無い。
      Impact 中 / Effort 小
- [x] **回答者への案件の配り方** — 答える人が自分の画面で見て、自分で取る形にした
      （`claim_invite`）。同じ案件を2人が取らないよう行を押さえる。
      言いにくい相談は、受けると決めた人にしか出さないし、取れない。
- [ ] P3 通知が無い（回答が来たことが分からない）

- [ ] P3 **通知が無い**（回答が来たことが分からない）
      メール基盤が無い。まず画面の中の通知だけでもよい。
      Impact 中 / Effort 中 / 依存：メール送信基盤
