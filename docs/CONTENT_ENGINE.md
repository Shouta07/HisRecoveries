# His Recoveries — コンテンツ配信エンジン（ハブ&スポーク）

> 目的: 1つの編集コンテンツ（原因解説 / feelings / 改善事例）を、各プラットフォーム向けに
> 量産し、**静かに、でも彼らが既にいる場所すべてに**届ける。源泉はサイト、各SNSはスポーク。
> 役割: 私（AI）が生成、あなた（or 自動化）が投稿、UTM で計測、勝ち筋を増幅。
> 関連: [`BUSINESS_PLAN.md`](./BUSINESS_PLAN.md)（§4 声・堀／§GTM）。

```
        ┌─────────── Threads / X / note（テキスト）
サイト ──┼─────────── Instagram カルーセル / 短尺動画（視覚・顔出しなし）
（ハブ） ├─────────── Reddit / 5ch / 知恵袋（誠実な回答＝信頼）
        └─────────── LinkedIn（toB・パートナー・投資家向け＝別読者）
                         ↓ すべて UTM 付きで Check / 原因ページ / Substack へ
```

## 0. ブランド共通ルール（全プロンプトで適用）

- 一人称・過去形。完了形（治った/克服した）を使わない。
- 処方・激励・呼びかけ（あなたも/〜しよう）をしない。医療の断定・診断・受診勧奨をしない。
- テストステロン/生産性/自己啓発/キラキラ美容/モテの語彙を使わない。
- 静か。短い文。余白。煽らない。**顔出しなし**（運営は匿名＝顔・実名・実年齢非公開）。
- 共感が主役、集客は結果。売り込まない。

## 2. UTM 規約

`?utm_source={pf}&utm_medium=social&utm_campaign={slug}`
（例: `...feelings/mirror?utm_source=threads&utm_medium=social&utm_campaign=mirror`）
→ `/admin/data` で PF 別・トピック別の Check 転換が見える。

## 3. 各プラットフォーム生成プロンプト

> 各プロンプトは「§0 ブランド共通ルールを適用」を前提とする。入力 = topic(slug) と素材。
> 出力は JSON（自動化が消費）。リンクは §2 の UTM を付与。

### 3.1 Threads / X（テキストの痛み）
```
役割: His Recoveries の編集者として、{pf} に投稿する日本語短文を書く。§0適用。
構造: 1〜3行の「生活の中の小さな痛み」を具体場面で（本体）。任意で半歩の転換一言。
任意で最後に1行＋UTMリンク。全体 Threads ~280字 / X ~130字。ハッシュタグなし。
配分: 約半分はリンクなしの純共感。連投で同一slugを避け6領域を巡回。
出力: {"text","link","topic","has_link"}
```

### 3.2 note（原因解説エッセイ・SEO）
```
役割: territories の原因解説を、note 向けの落ち着いたエッセイに展開。§0適用。
構造: 「なぜ起こるのか」を中心に、メカニズム→悪化要因→誤解→日本と海外→次の半歩。
1200〜2000字。見出しあり。最後に該当 territory と Recovery Check へ UTM リンク。
断定診断はしない。出典が要る箇所は「一般に〜とされる」に留める。
出力: {"title","body_markdown","canonical_link","topic"}
```

### 3.3 Instagram カルーセル（図解 / 悩み票）
```
役割: 1テーマを 6〜8 枚のカルーセル用に分解。§0適用。視覚は静かな余白基調・顔出しなし。
構造: 表紙(問い/痛み一言)→ なぜ起こるか を1枚1要素 → 誤解1枚 → 最後に静かな次の半歩。
各スライドは短文（〜40字）。キャプションに UTM リンク（プロフィール誘導でも可）。
出力: {"slides":[{"headline","sub"}],"caption","link","topic"}
```

### 3.4 短尺動画（Shorts / Reels / TikTok・顔出しなし）
```
役割: 30〜45秒の顔出しなし動画の台本。§0適用。映像は静かな情景（手元・洗面・窓・街）。
構造: 冒頭2秒で痛みの一言（フック）→ 5〜7の短いテロップで「なぜ」→ 余白で閉じる。
ナレーションは任意（淡々）。最後に「続きは概要欄」＋UTM。煽る編集をしない。
出力: {"hook","captions":[],"closing","link","topic"}
```

### 3.5 Reddit / 5ch / 知恵袋（誠実な回答）
```
役割: 男性が匿名で悩みを書いた投稿に、当事者の半歩先から誠実に答える。§0適用。
原則: まず役に立つ（メカニズム・選択肢の整理）。宣伝しない。最後に一度だけ、関連する
原因解説へ控えめにリンクしてよい（スパム禁止・コミュニティ規約厳守）。診断はしない。
出力: {"reply_text","link_optional","topic"}
```

### 3.6 LinkedIn（toB・パートナー・投資家＝別読者）
```
役割: 「男性の自意識」をカテゴリとして語る、事業者・投資家向けの知見投稿。§0の声は保ちつつ、
読者は当事者ではなく事業者。中立・データ・共創・"あいだ"の話を、誇張なく。
構造: 1つの洞察（例: なぜ中立が堀か / IoBを尊厳でやる）→ 短い論 → 控えめに about/network。
出力: {"text","link","topic"}
```

## 4. 運用ループ
```
私: 各PFのコンテンツを生成 → あなた(or自動化): 承認 & 投稿 → UTMでデータ returns
→ 私: /admin/data で PF別・トピック別の転換を読む → 勝ちPF/勝ちトピックを増産（複利）
```

## 5. 役割分担（正直に）
- **私が持つ**: 全PFのコンテンツ生成・プロンプト改善・サイト/SEO/GEO・計測整備・勝ち筋分析。
- **あなた(or 自動化)**: アカウント操作（実投稿）・声の最終承認・オフライン/パートナー。
- **私が単独でできない**: 外部アカウントへの実投稿、セッション跨ぎの常時運用。
  → だから「私が大量に作る → あなたが流す」ループにする。律速（制作）を私が引き受ける。

## 6. 広げすぎ対策
全PFを同時に完璧にしない。**テキスト3（Threads/X/note）を主軸**に、視覚2（IG/短尺）を併走、
信頼1・toB1 は機会次第。**勝ったPFにリソースを寄せる**（データで決める）。
