# His Recoveries × AI マーケティング実践プレイブック

> AIを「投稿の自動化」で終わらせず、事業の強み（一次情報＋中立＋思想）を
> 増幅・再配布・被引用させる装置として使う。Threads自動投稿・note記事化は前提として、その先の設計。
> 最終更新: 2026-07-07

---

## 0. 大原則 — AIは「増幅器」、源泉は人にしか作れない

| AIに任せてよい（増幅） | AIに任せてはいけない（源泉・信頼） |
|---|---|
| 下書き・リライト・要約・翻訳・分割 | 一次情報そのもの（取材・現場の事実） |
| 大量のバリエーション生成（投稿・見出し・LP） | 中立の判断・医療的な断定の線引き |
| リサーチ・キーワード発掘・データ要約 | 効果の約束・体験談の捏造（禁止） |
| 配信・スケジューリング・定型返信 | ブランドの思想・最終承認 |

**AIで薄い記事を量産しない。** 健康＝YMYL領域は、GoogleもAI検索も「一次情報・出典・E-E-A-T」を見る。
当社の勝ち筋は「AIが作れないもの（取材・中立）をAIで速く配る」こと。逆はSEOで沈む。

## 1. コンテンツ・リパーパス・エンジン（1 → N）

**これが最重要。** 1本の源泉（取材 or /areas記事 or 現場の気づき）を、AIで各チャネル用に増殖させる。

```
源泉（取材音声 / 記事 / メモ 1本）
   │  ① 文字起こし（Whisper系）
   │  ② 要点抽出・構造化（AI：ブランドボイスで）
   ▼
   ├─ /areas 記事（解説 or 取材記事：出典明記・人が最終編集）
   ├─ note 長文（当事者視点のエッセイ）
   ├─ Threads 連投 5〜8本（悩み共感→気づき→そっと導線）
   ├─ X ポスト 3〜5本（検索されるロングテール語を自然に）
   ├─ FAQ 追加（記事のQ&A → サイトFAQ → FAQPage schema）
   └─ 画像キャプション / OGP コピー
```

**運用**: 取材1本を録る → AIで6チャネル分の草稿を一括生成 → 人が15分で承認・微修正 → 予約投稿。
1回の源泉取得が、2週間分の配信素材になる。

## 2. チャネル別のAI活用

### 2-1. SEO（検索を取る）
- **キーワード発掘**: AIに「男性・第一印象・婚活・メイク初心者」周辺のロングテール質問を100個出させ、検索意図でグルーピング → /areas クラスタの制作リストに。
- **記事ドラフト**: ブランドボイス（§5）＋出典（MSD等の実URL）を渡して下書き → **人が事実確認・出典確認・トーン調整**して公開。AI丸投げ公開はしない。
- **FAQ量産**: 各記事から「読者が次に聞くこと」をAIに出させFAQ化 → FAQPage schema でリッチリザルト。
- **内部リンク提案**: AIに既存記事一覧を渡し、関連記事・体験導線の差し込み位置を提案させる。

### 2-2. GEO（AI検索に"引用される"）← 差別化の本丸
男性は恥ずかしい悩みほどChatGPT/Perplexityに聞く。**引用される情報源になる**のが最大レバレッジ。
- **質問＝見出し化**: AIに「読者がAIへ打つ自然文」を生成させ、記事のH2/FAQをその形に。
- **抽出しやすい一文**: 各記事冒頭に結論を1文で（断定でなく説明として）。要点3行は必須。
- **llms.txt を最新に保つ**: 実装済み。商品・4領域・引用ガイドを更新（AIへの"取扱説明書"）。
- **モニタリング**: 週1で ChatGPT/Perplexity に「AGA 初期症状」等を実際に聞き、**自社が引用されているか**を目視チェック → されてなければその記事を強化。GA4で chatgpt.com / perplexity.ai 経由流入も追う。

### 2-3. Threads / X（発見と共感）
- **既にやっている自動投稿を"質"で強化**: 投稿はAIで量産しても、必ずブランドボイス（§5）を通す。煽り・断定・効果約束をAIに禁止させる。
- **オケージョン投稿の自動生成**: 「婚活」「大事な日前」「ギフト」の切り口を月替わりでAIにシリーズ生成。
- **リプライ下書き**: 共感コメントにAIで下書き→人が送信（完全自動返信はブランド毀損リスク、下書きまで）。
- **スケジューリング**: Threads は公式API対応。Buffer / Typefully / Metricool / Make(旧Integromat) で予約投稿。Make なら「新記事公開→Threads連投を自動生成→下書きキュー」まで組める。

### 2-4. note / Substack（信頼の長文）
- 取材文字起こし → AIで当事者視点エッセイの骨子 → 人が魂を入れる。note→/areasへ被リンク（ドメイン権威）。

### 2-5. コンバージョン（サイト側）
- **LPコピーのA/B案**: ヒーロー・CTA・FAQの文言バリエーションをAIで複数生成 → 実データ（GA4）で選ぶ。
- **相談トリアージ**: 予約フォーム前に「3問で最適な入口を提案」する簡易ボットをAIで（将来）。まずは静的FAQで十分。

### 2-6. 取材・パートナー開拓（事業開発）
- **候補リサーチ**: Perplexity/AIで「メンズメイク・スタイリスト・婚活カメラマン」の発信者を発掘、プロフィール要約。
- **DM下書き**: §依頼テンプレをAIで相手ごとにパーソナライズ（相手の投稿に一言触れる）。
- **文字起こし→取材記事**: Whisperで文字起こし→AIで記事構成→本人確認。取材1本の記事化コストを激減。
- **VDソリューションの提案書**: 取材で見えた課題（§INTERVIEW_PROGRAM ⑤）から、AIで提案骨子を生成。

### 2-7. 分析・改善
- **GA4 / GSC を要約させる**: 週次で「表示回数・CTR・順位・流入元」をAIに貼って「次に書くべき記事・強化すべきページ」を提案させる。
- **勝ちパターンの横展開**: CVを生んだ記事/投稿の特徴をAIに分析させ、型として再利用。

## 3. 現実的なツールスタック（低コストで始める）

| 用途 | ツール例 | 備考 |
|---|---|---|
| 下書き・要約・リサーチ | Claude / ChatGPT / Perplexity | ブランドボイスをカスタム指示に保存 |
| 文字起こし | Whisper系 / Notta / tl;dv | 取材の一次情報化 |
| 予約投稿・自動化 | Make / Zapier ＋ Buffer / Typefully / Metricool | Threads公式API対応ツール |
| 画像 | Midjourney / nano-banana 等 | ⚠️ ビフォーアフターの捏造は禁止（景表法） |
| 計測 | GA4 / Search Console | AI経由流入の参照元を監視 |

**自動化の鉄則**: どのパイプラインも **「AI生成 → 人が承認 → 配信」** のゲートを必ず挟む。
YMYL＋匿名ブランドで完全自動配信は事故る。承認は1本15分で回せる設計に。

## 4. 90日ロードマップ

**Month 1 — 基盤**
- ブランドボイス（§5）をClaude/ChatGPTのカスタム指示に登録
- リパーパス・エンジンを手動で1周（取材or既存記事1本 → 6チャネル草稿 → 配信）
- GEOモニタリング開始（週1でAI検索に自社が出るか確認）

**Month 2 — 半自動化**
- Make で「記事公開 → Threads/X 連投を自動草稿 → 下書きキュー」を構築
- 取材の文字起こし→記事化フローを確立（月2本）
- GA4/GSC 週次AIレビューを習慣化

**Month 3 — 拡張**
- オケージョン投稿シリーズを月次で自動生成
- LPコピーA/Bを実データで選抜
- 引用されている記事を特定し、同型を横展開

## 5. ブランドボイス system prompt（コピペで使う）

> AIに毎回これを渡す。ブレとリスクを一発で抑える。

```
あなたは「His Recoveries」の編集者です。男性の第一印象・コンプレックスを扱う、
完全匿名・中立（売らない）・当事者視点のブランドです。以下を厳守して書いてください。

トーン: 静かで、誠実で、当事者の隣に立つ。煽らない。上から言わない。
禁止: 効果・成果の断定／「必ず」「治る」「若返る」等の完了形の約束／
      体験談の捏造／恐怖で煽る表現／特定クリニック・商品の推奨。
医療: 診断・治療は医療機関の領域と明記し、当社は医療行為をしないと分かる書き方。
出典: 事実を述べるときは出典を前提に（無ければ「一般に知られる」と留保）。
価値: 匿名・専属チーム・自分で探し回らない・はじめてでも、を軸に。
形式: 冒頭に結論1文 → 要点3行 → 本文。専門用語は噛み砕く。日本語。
最後に必ず: 断定していないか／効果を約束していないか を自己チェックして直す。
```

**チャネル別の追加指示例**
- Threads: 「140〜300字、1メッセージ1論点、絵文字は控えめ、最後は問いか静かな一言で。」
- note: 「2000〜3500字、当事者のエッセイ調、見出し3つ、最後に/areasへの自然な導線。」
- /areas記事: 「H2は読者がAIに打つ質問文。FAQ3問。出典URLは私が渡すものだけ使う。」

## 6. ガードレール（AI運用の禁止事項）

1. **薬機法・景表法**: 効果効能の標榜・誇大・ビフォーアフター捏造は禁止。AI出力も人が必ずチェック。
2. **E-E-A-T**: AIだけで書いた薄い記事を量産しない。一次情報・出典・人の編集を必ず通す。
3. **中立**: AIに特定院・商品を推奨させない。ランキング化しない。
4. **匿名・守秘**: 顧客・取材相手の個人情報をAIに入力しない（要配慮個人情報は特に）。
5. **完全自動配信をしない**: 公開前に人の承認ゲート。特に医療・センシティブ文脈。
6. **透明性**: 事実でないこと・体験していないことを、体験のように書かない。

## 7. KPI

| 層 | 指標 |
|---|---|
| 生産性 | 源泉1本あたりの派生コンテンツ数（目標6+）／記事1本の制作時間 |
| GEO | AI検索での自社引用回数（週次目視）／chatgpt・perplexity 経由流入 |
| SEO | オーガニック流入・掲載順位・インデックス数 |
| ソーシャル | 保存・プロフィール遷移・/apply への流入 |
| 事業 | 記事/投稿経由の予約・取材承諾・パートナー参画 |

> 北極星は変わらず「予約数」。AIは、そこへ至る"源泉→配布→被引用"を高速化する手段。
