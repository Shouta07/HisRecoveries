### 1-2. ユーザー心理：なぜ「悩み起点」が刺さらないのか

#### 【核心インサイト】
> **男性は「自分のため」には金を払わない。しかし「役割のため」なら払う。**

男性が高額の自己投資を正当化できるのは、支出の理由が**自分の欲望ではなく、
他者に対する責任・役割**に接続されたときだけ。

- 「肌をきれいにしたい」→ 払えない（自分の見栄＝浪費に感じる）
- 「3ヶ月後に登壇する。会社の顔として恥をかけない」→ 払える（**投資**に変わる）
- 「薄毛を治したい」→ 先送りできる
- 「半年後、式の写真が一生残る」→ 先送りできない（**締切がある**）

現在のLPは、この「正当化のアリバイ」をユーザーに一切与えていない。
ユーザーは自分で「これは自分のための美容支出だ」と認めなければ前に進めない。
**その承認コストが、実質的な第一関門になっている。**

#### 【心理その2】「悩みの自認」は敗北の承認である

ヒーロー直下のマーキー「こんなお悩み、ないですか？」は、共感の意図で置かれているが、
機能としては **入場条件として自己申告の敗北を要求している**。

- 「清潔感がない、って言われた」
- 「鏡の自分に、自信がない」
- 「写真の自分が、嫌いだ」

この文言に「はい、私です」と心の中で答えられる男性しか、次のセクションへ進めない。
そして皮肉なことに、**最も支払い能力の高い層（経営者・管理職・専門職）ほど、
自分を敗者カテゴリに置くことへの抵抗が強い**。

現在のLPは、構造的に **払える人を弾き、払えない人を集める** 設計になっている。

#### 【心理その3】男性は「治療」ではなく「準備」に金を払う

- 治療＝自分に欠陥があることの証明 → 恥
- 準備＝重要な機会に向けた合理的行動 → 誇り

やっていることが同一（AGA治療・スキンケア・スタイリング）でも、
フレーミングが「治療」か「準備」かで、支払い意欲と自己肯定感が真逆に振れる。
**シーン起点とは、同じ商品を「準備」として再パッケージすることに他ならない。**

#### 【心理その4】「変わりたい」は、実は行動の動機として弱い

「変わりたい」は願望であって、締切も合格ラインもない。
一方、「結婚式が10月」「4月に昇進面談」「息子の運動会」には、
**日付と、評価者と、やり直せない性質** がある。
行動を起こすのは願望ではなく締切である。現在のLPには締切がない。

### 1-3. 購入までの障壁（5つの壁）

| 壁 | 内容 | 現在LPの対応 | 評価 |
|---|---|---|---|
| **① 認知の壁** | 自分が「美容」を必要としていると認めたくない | 悩みマーキーで認めさせにいく | ❌ **逆行している** |
| **② 相手の壁** | 誰に相談していいか分からない／笑われたくない | 匿名・NDA・当事者運営 | ✅ 強い |
| **③ 判断の壁** | 何が効くか、どの順番か分からない | パッケージ自動編成＋日程プラン | ✅ **解決済み**（後述） |
| **④ 金の壁** | 総額が読めない、ぼったくられる恐怖 | Recover/Refineとも「要相談」 | ❌ **自己矛盾** |
| **⑤ 露見の壁** | 会社・家族に知られたくない | NDA・実名不要 | ✅ 強い |

**最大の問題は ① と ④。**

**④の自己矛盾について**：LP自身が「ぼったくられるのが、怖い」というユーザーの声を
掲示しておきながら、プランの価格は Recover / Refine ともに「要相談」。
明示されている具体価格は入口の ¥22,000 のみ。
これは「怖がっている人に、まさに怖いものを見せている」状態。
「明朗会計」を3カラムで謳っているのに、料金表に金額がない — この落差が最も信頼を削る。

**③について — 診断は `PackagePlanner` で解決済み。残るのは「入口」だけ**

> 【更新】旧 `QuickDiagnosis`（悩みチップを選ぶと固定順に並べ替えて記事を出すだけ＝入力＝出力）は、
> **`PackagePlanner`（パッケージ自動編成＋日程プラン）に置き換え済み**。本節の旧批判は解消された。

現行 `PackagePlanner` / `lib/planner.ts` が既に実現していること：

- **入力**：都道府県・年齢・やりたいこと（複数選択）・自由記述
- **出力① 構成**：選ばれたモジュールと**費用の内訳＋合計の目安**（例 ¥197,000〜）
- **出力② 日程プラン**：最寄り拠点・移動時間から集合時刻を決定。7時間超は2日に分割、
  4時間超は昼休憩を挿入。事前(オンライン)→前日(遠方のみ)→当日→後日の4段構成
- **出力③ 読みもの**：構成の重心順に領域別の記事
- **束ね方の一文**：「薄毛の現在地を先に押さえる → 髪と眉で土台を上げる → …」と順番の理由を説明
- **年代別の重心**：「40代のあなたへ：『若く見せる』より『疲れて見せない』」
- **正直さのガードレール**：医療は「中立紹介」バッジで分離、提供範囲外（歯科・美容外科等）は
  黙って落とさず注記、価格・所要はすべて「目安」と明示

これは **NEWT型の診断そのもの**である。「情報の非対称性の解消」も「診てもらった感」も成立している。
実際に北海道・42歳・自由記述「半年後に結婚式」で試すと、札幌拠点・出張チーム編成・約4週間の
リードタイム・2日構成・¥197,000〜まで自動で返る。**判断の壁への回答としては、ほぼ完成している。**

**したがって、残る課題は診断エンジンではなく、その手前の2点に絞られる。**

| 残る課題 | 現状 | 必要な手当て |
|---|---|---|
| **A. シーンが「入口」になっていない** | 自由記述の正規表現（`TEXT_RULES`）で結婚式・婚活・仕事の場面等を**事後的に検出**している。書かなければ検出されない | シーンを**第一級の入力**に昇格。S2のカードから `occasion` を引き継いでプランナーへ渡す |
| **B. 締切（日付）の入力欄がない** | 「半年後」と書いても構成には反映されるが、**残り日数の概念がない**。現在の「日程プラン」は当日の時間割であって、D-180からの逆算ではない | `targetDate` を任意入力として追加し、カウントダウンと逆算カレンダーを生成 |

補足：`続かなかったこと`（除外条件）と`露見リスク`（手配方法の設計）の設問も未実装。
Bの次に効く。

**まとめ：診断エンジンは作り終えている。足りないのは「シーンから入り、締切から逆算する」入口の一枚。**
本提案の実装コストは、当初想定より大幅に小さい。

#### 追加の障壁：Recover / Refine が自己判定できない

- 「取り戻す」「深める」は**運営側の分類語**であり、顧客の自己認識の語彙ではない。
- 顧客は「自分はゼロ以下なのか、プラスなのか」を自己判定できない（かつ、したくない）。
- さらに Refine には「一部準備中」バッジ。**買えない商品が棚に並んでいる**状態で、
  「まだ体制が整っていない会社」という印象を与えている。

#### 追加の障壁：成果の証拠がゼロ

`lib/recoveries.ts` に「実例集（Recoveries）」の仕組みが実装済みなのに、
**トップLPに一切露出していない**。
「変わった男が実在する」証拠がない状態で、¥150,000〜の意思決定は起きない。

### 構造上の3つの設計判断

**判断1：シーンは「選ばせる」、悩みは「診断が言い当てる」**

ユーザーに自己申告させるのはシーン（＝恥ずかしくない情報）のみ。
悩み（＝恥ずかしい情報）は、診断の質問を通じて **こちら側が推定して提示する**。
「自分で認める」から「言い当てられる」への転換が、認知の壁を無効化する。

**判断2：診断の出力は「順番」ではなく「締切からの逆算カレンダー」**

現在の出力は順番（何から）。新しい出力は日程（いつまでに何を）。
締切がある人にとって、順番だけでは行動が起きない。
AGAの発現に3〜6ヶ月、肌のターンオーバーに1〜3ヶ月かかるという**医学的な所要時間**が、
そのまま「今日始めるべき理由」になる。煽りではなく事実で緊急性を作る。

**判断3：悩み軸（6領域）は「診断結果の内部言語」として残す**

`/areas/{id}` の6領域とコンテンツ資産はそのまま活用する。
シーン → 診断 → **その人に必要な領域だけ** が結果画面に現れる、という接続に変える。
LPトップの一覧棚としては置かず、フッターとSEOランディングに残す。

## ③ ファーストビューのコピー案

### 【採用済み】ブランドの3層（実装反映済み）

抽象度の異なる3つを、別のレイヤーとして配置する。1枚のコピーに全部を背負わせない。

| 層 | コピー | 置き場所 |
|---|---|---|
| **上位概念** | **理想の男に、最短距離で。** | ヒーロー見出し |
| **売る入口** | **大切な場面で、自信を持てる自分へ。** | Job選択セクションのラベル |
| **提供価値** | **あなたに必要な変化の順番を設計する。** | 同セクション本文 → 診断 |

**ヒーロー・サブコピー：**

> **恋愛、仕事、人生の節目。**
> **あなたが叶えたい未来から逆算し、**
> **必要な変化の順番を設計する**
> **男性ウェルネスコンシェルジュ。**

このコピーが解決していること：

- **「恋愛、仕事、人生の節目」** — Job起点を1行目で宣言。悩みの自認を要求しない
- **「叶えたい未来から逆算」** — NEWT型（達成したい未来 → 逆算）の思想をそのまま言語化
- **「必要な変化の順番を設計する」** — 提供価値を明示（＝提供価値の層と一致させている）
- **「男性ウェルネスコンシェルジュ」** — カテゴリを自己定義。「美容医療紹介サイト」との差別化を
  ここで確定させている

> 実装：`src/app/page.tsx`。文節単位の `inline-block` で、狭い画面でも語の途中で折れない。

**なぜ「理想の男に」を上位概念に留め、売る入口にしないのか**

ここが本設計でいちばん重要な判断。

> **「理想の男になりたい」という抽象的な欲求だけでは、人は財布を開かない。**

NEWT が成立しているのは「最高の人生を送りたい」を売っているからではなく、
**「この日程で、この旅行を失敗なく実現したい」**という具体を解いているから。
HR も同じで、実際に売るのは **人生イベント × 男性改善** の粒度でなければならない。

だから「理想の男に、最短距離で。」はブランドの旗として掲げるに留め、
その下に**必ず具体のJob（5つ）と、可能なら日付**を置く。
実装上もこれを守っており、`bigday` / `work` シーンには締切（`targetDate`）を入力させ、
残り日数から「間に合う／間に合わない」まで判定する。**抽象で集めて、具体で売る。**

以下は、さらにシーン起点を強めたい場合の見出しごと差し替える案（参考）。

### 設計条件
- 「美容」「ケア」「悩み」「コンプレックス」の語を**一切使わない**
- 「変わりたい」（願望）ではなく「その日がある」（事実）から始める
- 男性が声に出して読める硬度を保つ（可愛くしない・軽くしない）
- 既存のブランドトーン（深緑・明朝・簡潔）を崩さない

### 【A案｜推奨】「その日」起点

> **人生には、**
> **失敗できない日がある。**
>
> 登壇。結婚式。家族との写真。勝負の商談。
> その日、最高の自分でいるために、
> 何を、いつまでに整えるか。
> ——男性専門のコンシェルジュが、設計します。
>
> `[ 30秒でわかる、あなたの現在地 → ]`
> ※無料・匿名・登録不要／秘密保持のもとで

**推奨理由**：
- 「失敗できない日がある」は**全男性が同意できる事実命題**であり、
  自分を悩んでいる側に置く必要がない
- 4つの単語（登壇／結婚式／家族との写真／商談）が、そのまま次セクションの入口を予告する

## ④ シチュエーション別の商品設計

### ④-0. Job体系 — 5つのJob（実装済み）

ジョブ理論（JTBD）で整理する。HRが雇われる仕事（Job）は
**「理想の自分になるために、必要な変化を最短距離で実現すること」**。
ただし前述のとおり、抽象のままでは売れないので、**5つの具体Jobに分解**して入口にする。

各Jobは3層で保持する（`src/lib/occasions.ts`）：

| 層 | フィールド | 役割 |
|---|---|---|
| 顧客が選ぶ言葉 | `purpose` | 叶えたいこと。恥ずかしくないので自己申告できる |
| **本当のJob** | `job` | お金を払う理由。カードで言い当てる |
| 表面的な悩み（What） | `obstacles` | **現在の障害**。Jobと診断のあいだを埋める |

| # | ID | 叶えたいこと（`purpose`） | 本当のJob（`job`） | 表面的な悩み（`obstacles`） | 締切 |
|---|---|---|---|---|---|
| 01 | `romance` | 恋愛で、選ばれる自分になりたい | 自信を持って、女性と向き合える自分になりたい | 肌荒れ／髪型／服／体型 | — |
| 02 | `bigday` | 大切な日に、最高の自分でいたい | 人生の節目で、最高の自分として記録を残したい | 写真写り／清潔感／肌 | ✅ |
| 03 | `work` | 仕事で、信頼されたい | 能力だけでなく、見た目でも信頼される人間になりたい | 服装／髪／姿勢／印象 | ✅ 任意 |
| 04 | `family` | 家族に、誇られる存在でいたい | 大切な人から、魅力的な存在であり続けたい | 老け見え／体型／身だしなみ | — |
| 05 | `restart` | もう一度、自分を好きになりたい | 昔の自分以上に、自分を好きになりたい | 疲れ顔／自信の低下／習慣の崩れ | — |

> **「恋愛で自信を持ちたい」と「魅力的な男性になりたい」は同一Jobとして 01 に統合**した。
> 選択肢として並べると顧客が迷い、しかも両方とも同じ構成に着地するため。
>
> **`obstacles` の使い方が設計上の要点。** 表面的な悩みは、カードには出さず、
> **Jobを選んだ直後に「ここで、よく壁になるもの」として提示する**。
> 自分で悩みを認めるのではなく、こちらが先に言い当てる形にすることで、
> 認知の壁を踏まずに診断へ渡せる。これが Job → 現在の障害 → 診断 の接続。

**6商品との対応**（下の詳細設計は、この5シーンに畳んで運用する）

| シーン | 対応する商品 | 備考 |
|---|---|---|
| 01 恋愛・魅力 | **Attract｜選ばれる男に** ¥150,000〜 | 新設。婚活・デート文脈。旧6案にはなかった枠 |
| 02 人生の大切な日 | **The Day** ¥250,000〜 | 旧 The Groom を拡張（結婚式に加え、プロポーズ・記念写真・婚活写真） |
| 03 仕事・社会的信頼 | **Presence** ¥180,000〜 | そのまま |
| 04 家族・パートナー | **Family** ¥150,000〜 | 旧 Again ＋ Father を統合（妻と子を分けず「家族」で束ねる） |
| 05 自己再起 | **Restart** ¥150,000〜 | Redesign（年間・血液依存）は、このシーンの**上位プラン**として Phase 2 で解禁 |

> 統合の理由：Again（妻）と Father（子）は、顧客心理も提供内容も提携先も重なる。
> 別商品として売り分けるより「家族に誇られる」で束ねたほうが、顧客が自分を指させる。
> Redesign は独立商品ではなく Restart の年間版に位置づけることで、
> 血液（`preparing`）の解禁を待たずに **シーン05を今日から売れる**状態にできる。

- **入口は全商品共通で「印象診断 ¥22,000（申込で全額充当）」** に統一する。
  商品ごとに入口を変えない — これが「診断→設計→接続」というHRの一貫した骨格を守る。
- 6商品はすべて、既存の供給（第一印象チーム・診断・伴走）の**組み替えと文脈の付与**であり、
  新規の仕入れをほぼ必要としない。**供給を増やさずに単価と成約率を上げる設計**である。

## ⑤ Recover / Refine の再定義

### 現在の問題

| | 現在 | 問題 |
|---|---|---|
| Recover | 取り戻す | 「何を失ったか」を認めないと選べない |
| Refine | 深める | 「自分は既に整っている」という自己評価が必要 |

**両方とも、顧客に自己評価を要求している。** そして男性は自己評価を避ける。
さらに「Refine＝一部準備中」の表示が、選択肢としての信頼性を下げている。

### 再定義：概念は維持し、判断基準を「時間軸」に置き換える

> **Recover ＝ いま、間に合わせる**（マイナスをゼロへ／締切がある）
> **Refine ＝ この先、崩れない**（ゼロをプラスへ／締切がない）

自己評価（自分は下か上か）ではなく、**状況の客観的事実（締切があるか）** で分岐する。
これは顧客が100%正しく自己判定できる基準であり、かつ元の思想を損なわない。

### 顧客向けの説明文（LP掲載用）

---

#### **Recover｜取り戻す**
> **いま、間に合わせる。**
>
> 大事な日が決まっている。あるいは、もう待てない。
> そういうときは、期日から逆算して、**効くものだけ**をやります。
> 全部はやりません。間に合うものを、間に合う順に。
>
> `▸ こんな方に`　式が半年後／登壇が決まった／転職活動を始める／もう先送りしたくない
> `▸ 期間`　1日〜6ヶ月　`▸ 入口`　印象診断 ¥22,000（お申し込みで全額充当）

#### **Refine｜深める**
> **この先、崩れない。**
>
> 締切はない。けれど、5年後の自分は今日の積み重ねでできている。
> 一度整えた状態を、**考えなくても維持できる仕組み**にします。
> 現状維持は、ゆるやかな後退だから。
>
> `▸ こんな方に`　一度整えたが維持できていない／老けの先手を打ちたい／年単位で設計したい
> `▸ 期間`　3ヶ月〜12ヶ月　`▸ 入口`　印象診断 ¥22,000（お申し込みで全額充当）

---

### 運用ルール：顧客に選ばせない

- **LPの選択肢としては提示するが、意思決定は診断が行う。**
  診断結果画面で「あなたは **Recover** から始めるのが最短です（式まで残り164日のため）」と
  **理由つきで断定する**。
- 「一部準備中」バッジは廃止。準備中の**構成要素**（血液など）は該当箇所にのみ注記する。
  商品全体を準備中に見せない。
- 多くの顧客は **Recover で入り、達成後に Refine へ移行する**。
  これを分岐ではなく **時間軸上の連続（Recover → Refine）** として描くと、
  LTV設計とも一致する。

```
  Recover                    Refine
  ──────────────→  その日  ──────────────→
  間に合わせる               崩れない
  （締切あり）                （締切なし・継続課金）
```

### Job別ランディングページ（Step 4）の設計

`/occasions/{id}` — 広告・検索の着地先。5本すべて静的生成。

**設計上の要点：構成と費用を、文言として書き起こさない。**

ページの「構成の一例」と「合計の目安」は、ビルド時に `composePlan()` を
呼んで生成している（東京・35歳を前提として明記）。
つまり **LPのプランナーと同じエンジンから出る**ので、
価格を二重管理せずに済み、片方だけ更新して嘘をつく事故が起きない。
実測で `/occasions/bigday` の表示は ¥197,000〜、プランナーの同条件出力と一致。

**セクション構成**（Job → 現在の障害 → 順番 → 構成 → 逆算 → 実行者 → FAQ → CTA）

| セクション | 内容 |
|---|---|
| ヒーロー | `no` / `purpose` / `title` / **`job`（本当のJob）** / `examples` |
| 現在の障害 | `obstacles` ＋「全部やる必要はありません」 |
| 整える順番 | `plan.synthesis`（`flowLead` ＋ モジュール順の説明） |
| 構成の一例 | `composePlan()` の出力そのまま。中立紹介バッジ・価格内訳つき |
| **逆算** | `dated: true` のJobだけ表示。髪3〜6ヶ月／肌1ヶ月／脱毛複数回／直前で効くもの、を明示 |
| 誰が実行するのか | `partners`（種別のみ。個社名は出さない）＋ 中立の3約束 |
| FAQ | Job固有。`FAQPage` の構造化データつき |
| CTA | `/?occasion={id}#diagnosis` → プランナーがJob選択済みで開く |

**導線の接続**：`SceneFlow` が `?occasion=` を読み、Jobを選択済みにする。
`useSearchParams` ではなく `location` を読むのは、トップLPを静的なまま保つため
（`useSearchParams` は Suspense 境界を要求し、ページが動的になる）。

**検証の優先順位**：`focus: true` は `bigday` / `work` の2つ。
締切が最も強い（bigday）と単価が最も高い（work）を先に検証する。
sitemap でも他より高い優先度（0.95）で出している。
残り3つ（`romance` / `family` / `restart`）は締切がなく行動理由が弱いため、
広告投下は 02・03 の結果を見てから判断する。

**測定すべきKPI（改修前後で比較）**
- FV → S2 のシーン カードクリック率（新指標・最重要）
- 診断開始率／診断完了率（現行の悩みチップ選択との比較）
- 診断完了 → 相談予約の転換率（**現在の最大のボトルネックと想定**）
- 相談 → 印象診断（¥22,000）の成約率
- シーン別の平均単価と成約率（どのシーンが最も売れるかを実データで確定させる）

## 最後に：この再設計が守っているもの

本提案は、His Recoveries の既存資産を1つも捨てていない。

| 既存資産 | 本設計での扱い |
|---|---|
| 6つの悩み領域と記事資産 | 診断の内部言語＋フッター＋SEO着地点として温存 |
| 匿名・NDA・当事者運営 | **シーン起点でむしろ価値が上がる**（新郎も経営者も、知られたくない） |
| 印象診断 ¥22,000 の入口 | 全商品共通の入口として統一・強化 |
| 第一印象パッケージ ¥150,000〜 | 6商品すべての実行エンジン |
| 紹介料を受け取らない中立性 | S8で正面から商品価値として提示 |
| Recover / Refine | 概念を維持し、判断基準のみ時間軸へ置換 |
| 実例（Recoveries）の仕組み | 未使用だった資産をLPで解放 |
| パッケージ自動編成＋日程プラン | **本設計の心臓部としてそのまま使う。シーンと締切を足すだけ** |

変えたのは、**入口の一枚だけ**である。

> 「悩みのある男性が、悩みを解決しに来る場所」
> →
> **「大事な日を控えた男性が、準備をしに来る場所」**

同じ商品、同じパートナー、同じ価格。
しかし、来る人と、払える金額と、決断までの速度が変わる。
