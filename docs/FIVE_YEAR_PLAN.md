# His Recoveries — 5年事業計画（Y1–Y5）

> 世の中に、自信にあふれた男性を増やし続ける。
> 男性の回復体験をプロデュースするブランド、His Recoveries。

最終更新: 2026-06-14 ／ 運営: バイタリティデザイン合同会社
前提となる戦略・原則は [`BUSINESS_PLAN.md`](./BUSINESS_PLAN.md) を参照。

---

## 読み方（重要）

- 期間: Y1 = 2026 下期〜2027、以降1年刻み（Y5 = 2030）。
- 数値はすべて **目標（仮説）**。実データが無い段階の断定予測ではない。各年の実績で更新する。
- **ゲート制**: 前年の中核ゲートを満たさない限り、翌年の収益化に進まない。
  順序（権威・データ → パートナー → 収益化 → 海外）を崩さない。
- 北極星: 「自信を取り戻した」と言える男性の数（回復体験の完了・継続）。

## Year 1 — 発信と収集（Phase 0 → 早期 Phase 1）

**目的**: 原体験 × 編集で、信頼と一次データの土台を作る。まだ売らない。

- 施策
  - 日本で発信（Threads 自動化 + 編集、SEO/GEO の熟成）。痛みの言語化 → Recovery Check。
  - Recovery Check / Stories / Recoveries Letter の運用。改善事例ループを回す。
  - `/admin/data` で一次情報を読み、認証基準の初版を実データで調整。
- ゲート（達成しなければ Y2 の認証に進まない）
  - **Recovery Check 100件 / 改善事例 10件 / Letter の継続購読が立ち上がる**
- KPI 目標（仮説）
  - Check 完了 100〜300件、完了率 ≥ 5%、Letter 購読 50〜150
- 収益: ほぼゼロ（Letter のみ）。投資フェーズ。
- 体制: 編集1人 + DX 開発本業。

## Year 2 — 認証の確立（Phase 1 → 早期 Phase 2）

**目的**: 集めた一次理解を根拠に、日本の最初のパートナーを認証する。

- 施策
  - 最初の **5〜10 院/サロン/専門家**を認証（覆面審査・年次更新・剥奪公開）。
  - **バッジ契約**開始（Recovery Certified）。認証は中立に保ち、収益はバッジ年会費へ。
  - Recovery Data 内部版を運用し、認証基準・コンテンツに再投資。
  - Low-end 体験パッケージの最小検証（デジタル中心、医療は橋渡しのみ）。
- ゲート
  - **認証維持率が健全（安易に増やさない）／ 信頼ベースの送客が機能する**
- KPI 目標（仮説）
  - 認証 5〜10、Check 累計 1,000〜3,000、Letter 購読 300〜800
- 収益: Letter + バッジ年会費 +（小規模）Low-end パッケージ。
- 体制: 覆面審査の外部協力、編集の文書化（声・基準）。

## Year 3 — 体験と商品（Phase 2 → Phase 3 入口）

**目的**: 回復体験パッケージと共同商品で、toC/toB の収益を立ち上げる。

- 施策
  - **High/Low パッケージ**を本格運用（医療 × サロン × デジタルデトックスの掛け合わせ）。
    ※ 医療を含む設計は法務レビュー（医療広告規制等）通過が前提。医療はパートナー主体。
  - 提携パートナーと **共同商品をローンチ**（レベニューシェア）。
  - 認証ネットワークを地域・カテゴリで拡張（質を保ちつつ）。
- ゲート
  - **High-end の継続率・満足度が立つ／ 共同商品が再現性を持つ**
- KPI 目標（仮説）
  - 認証 20〜40、パッケージ提供 数十〜百件規模、共同商品 初年度売上
- 収益: 体験パッケージ + 共同商品 + バッジ + Letter の複線化。
- 体制: 編集チーム化、パートナー開発担当。

## Year 4 — システムとループ（Phase 3）

**目的**: パートナー向けシステムで現場の一次情報を基盤化し、データを還元してスケールする。

- 施策
  - **パートナー向けシステム開発を受託 / SaaS 化**（顧客理解・改善データが貯まる基盤）。
    バイタリティデザインの toB AI・DX 本業と直結。
  - **Recovery Data を B2B 提供**（匿名集計の知見）。
  - ループ（貯める → 学ぶ → 還す）を仕組みとして定常運用。
  - 海外の準備: 英語コアを育て、海外事例・候補パートナーの発掘。
- ゲート
  - **データループが収益と改善の両方を生む／ 海外展開の型が見えている**
- KPI 目標（仮説）
  - システム導入パートナー数、Recovery Data 契約、ネットワーク 50+
- 収益: システム（受託+継続）+ データ + 体験 + 商品 + バッジ。最も多角化。
- 体制: システム開発体制、データ・編集の分業。

## Year 5 — 世界へ（Phase 4）

**目的**: 世界共通の課題として、海外の事例とパートナーを巻き込み、カテゴリを定義する。

- 施策
  - 英語圏（または1〜2の先行市場）へ展開。フル i18n、現地コンプラ、**現地認証**を開始。
  - 海外パートナーとの認証・共同商品・データ連携。
  - 「Male Conditioning」を、男性の回復体験の**カテゴリ語**として定着させる。
- ゲート
  - **海外で最初の認証 / 体験 / データが回り始める**
- KPI 目標（仮説）
  - 海外認証 初の数件、英語 Check の立ち上がり、グローバルでのブランド言及
- 収益: 国内の複線収益 + 海外の初期収益。
- 体制: 日本拠点 + 海外パートナー網。支社・現地運用の検討。

```
Y1 |■                      Letter のみ（投資期）
Y2 |■■■                    + バッジ年会費 + Low-end
Y3 |■■■■■■                 + 体験パッケージ + 共同商品
Y4 |■■■■■■■■■              + システム + Recovery Data（多角化）
Y5 |■■■■■■■■■■■            + 海外初期収益
```
※ バーは相対的な立ち上がりイメージ。金額は実データでモデリングする（本書では断定しない）。

## 全期間で守る原則（崩すと価値が消える）

1. **順序**: 権威・一次データ → パートナー → 収益化 → 海外。早すぎる収益化をしない。
2. **中立**: 認証で紹介手数料・広告費を取らない。認証と収益源を分離する。
3. **質 > 数**: 認証・パッケージ・パートナーは少数精鋭から。剥奪を恐れない。
4. **編集の独立**: 認証する相手から、編集は構造的に独立し続ける。
5. **当事者の尊厳**: 匿名化徹底、PII を出さない、沈黙を尊重する。
6. **法務ゲート**: 医療を含む設計は専門家レビュー後にのみ進める。

## 主要リスクと、年次での見張りどころ

| リスク | 主に注意する年 | 防御 |
|---|---|---|
| 早すぎる収益化で中立毀損 | Y2–Y3 | ゲート厳守・収益源分離 |
| 医療・広告規制 | Y3〜 | 法務レビュー・医療はパートナー主体 |
| 編集属人・スケール限界 | Y3–Y4 | 文書化・編集チーム化 |
| データ倫理 | 全期間 | 匿名化・尊厳優先 |
| 海外の現地化コスト | Y5 | 需要が立ってから・型の移植に限定 |
