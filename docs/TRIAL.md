# 体験の受け付け（/trial）

更新 2026-10-03

Stripe の審査が終わるまでのあいだ、相談する人の入口になる面。
**お金は受け取らない。** 1件を手で届ける。

---

## なぜ要るか

いま、相談する人の道はここで止まっていた。

```
トップ → /ask → 迷っていることを書く → お支払い → 止まる
```

`/ask` は、受け付けられないときに先にそう言う（書いたあとに止めない）。
正しいが、そこから渡していたのは **通話の順番待ち（/talk）だけ** だった。
通話は受付前の商品なので、来た人に渡せるものが1つも無かった。

文章の相談は、決済が無くても手で届けられる。そのための面。

---

## 何を約束しているか

画面に出している約束は、これだけ。
**ここを増やすと、手で回せなくなる。**

| | |
|---|---|
| 返すもの | `plans.ts` の `first`（はじめの1件）と同じ。女性1人が読む |
| お金 | かからない。お支払いの手続きも出さない |
| 返事 | **72時間以内**にメール（`TRIAL_REPLY_HOURS`） |
| 1日に受ける数 | 5件（`TRIAL_PER_DAY`）。超えた分は順番待ちとして受ける |

数字は `src/lib/trial.ts` の1か所。変えると画面の文も一緒に変わる。
手で書いた数字はどこにも無い。

### 残り枠を画面に出していない

出すには数える必要があり、数えるには保存先が要る。
保存先が無いときに「あと3枠」と書くと、それは作り物の残り枠になる。

受けられる数は API 側で止める。画面では約束しない。

---

## 届いたものを見る

Supabase の SQL エディタで:

```sql
select * from trial_queue;
```

`trial_queue` は、返していないものだけを、待たせている順に出す。

| 列 | |
|---|---|
| `status` | `new` = 体験として受けた／`waitlist` = 回答者が揃っていない向き |
| `asker_gender` | どちらの回答者に渡すか |
| `topic` | 確かめたいこと（**伏せ字をかけたあと**）。任意なので空のことがある |
| `redacted` | 何を伏せたか |
| `waiting_hours` | 何時間待たせているか。72 を超えたものが上に来る |

返し終わったら:

```sql
update trial_bookings set status = 'done', contacted_at = now() where id = '...';
```

連絡だけ済んでいるなら `status = 'contacted'`。

---

## 順番待ちになる2つの場合

どちらも**断らずに受ける**。断ると、その人が何人来たのかが分からない。
分からないままだと、回答者を集める理由が作れない。

### 1. 回答者が揃っていない向き

いま `ASKER_OPEN`（`src/lib/who.ts`）は男性だけ `true`。
女性からの申し込みは `status = 'waitlist'` で入る。

**男性の回答者が3人揃ったら** `ASKER_OPEN.female` を `true` にする。
画面の断りは自動で消える（消し忘れると判定が止める）。

### 2. その日の受け入れ数を超えた

6件目からは `waitlist` で入る。翌日に回す。

---

## 保存先が無いときに何が起きるか

`SUPABASE_URL` / `SUPABASE_SERVICE_KEY` が入っていないと、
API は **503 を返す**（「受け付けました」と嘘をつかない）。

このとき画面は、同じ内容をメールで送るボタンに切り替わる。
本文は書いたものから組み立てるので、**書いたものは消えない**。

```
宛先  contact@vitality-design.jp
件名  体験のお申し込み
本文  わたし: 男性 ／ 確かめたいこと: （伏せ字をかけたもの）
```

メールの道でも伏せ字はかかる（画面の約束を片方の道で嘘にしないため）。

> **公開の前に確かめること**
> `trial_mailto` のイベントが出ているあいだは、保存先が効いていない。
> 広告を回す前に、Supabase の鍵が本番に入っているかを見ること。

---

## 設定

| 環境変数 | |
|---|---|
| `TRIAL_OPEN` | `0` にすると受け付けを閉じる。既定は**開いている** |
| `SUPABASE_URL` / `SUPABASE_SERVICE_KEY` | 無いとメールの道に切り替わる |

開くために設定を入れる形にしていない。
そうすると、開き忘れたまま広告が走る。

---

## Stripe が通ったら

`/trial` を消す必要はない。体験は体験として残る。

- 決済が開くと、`/trial` の下に続け方が金額付きで出る（`readyToSell()` を見ている）
- `/ask` の行き止まりの画面は、そもそも出なくなる
- 体験を止めるなら `TRIAL_OPEN=0`
