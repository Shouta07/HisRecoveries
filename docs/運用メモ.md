# 運用メモ（運営者向け）

サイトには出ない、運営する側の手順です。

---

## 1. いまの段階

tashikame.app は **構想を公開する面** です。売っているものはありません。

| | |
|---|---|
| 掲載しているもの | 旅先と客室をつなぐ体験の構想（Experience OS ＋ Kit） |
| 最初の市場 | 東京・浅草／蔵前 |
| 最初に作る大きさ | 1エリア × 1宿 × 3〜5スポット × 1室 |
| 売っているもの | なし。申し込み・請求・決済の口は置いていません |
| 連絡の口 | メールだけ（`NEXT_PUBLIC_CONTACT_EMAIL`） |

前の相談サービス（LINE・Google Meet・3,980円）は畳みました。
その面・規約・特商法の表記・決済クライアントはすべて消してあり、
古いURL（/pricing /about /cities /stories /en /zh）はトップへ転送します。

## 2. 公開前に設定が要るもの

| 環境変数 | 何を入れるか | 入っていないとどうなるか |
|---|---|---|
| `NEXT_PUBLIC_CONTACT_EMAIL` | 連絡を受けるメール | 「連絡先は準備中です」の押せない表示のまま。**これが無いと、読んだ宿が連絡できません** |

**消すもの**（残っていると公開前にビルドが止まります）：

| 環境変数 | なぜ消すか |
|---|---|
| `STRIPE_SECRET_KEY` | 売っていないのに決済の鍵があると、表記の無いまま請求が通る形になる。`lib/legal.ts` が止めます |
| `STRIPE_PASS_PRICE_ID` `STRIPE_WEBHOOK_SECRET` | 同上。決済クライアントは消したので、読んでいる場所もありません |
| `NEXT_PUBLIC_LINE_URL` `NEXT_PUBLIC_PAY_URL` | 畳んだ相談サービスの口。読んでいる場所はもう無い |

## 3. 構想の中身を変えるとき

中身は `src/lib/concept.ts` が1か所で持っています。面は引くだけです。

| 変えたいもの | どこ |
|---|---|
| 一日の流れ（8段） | `JOURNEY` |
| まだ無いもの | `NOT_BUILT` ← **空にすると公開前に止まります** |
| 最初の市場・エリア | `MARKET` |
| 声をかけたい宿の姿 | `ICP` |
| 声をかけない相手 | `NOT_FOR` |
| 話したい相手 | `TALK_TO` |
| 「これではない」 | `NOT_THIS` |

### 止まる条件（`concept.ts` と `scripts/check-concept.mjs`）

- 値段（円・¥・JPY）が構想の文に入る（ICPの「1泊の単価」だけ例外。同じ文に「1泊」か「単価」が要る）
- 申し込み・購入・今すぐ・Stripe・LINE の語が、どこかに残る
- `NOT_BUILT` が3件未満、または「宿が無い」「機材が無い」が抜ける
- 導入実績・利用者数・満足度・お客様の声
- 例に京都が残る（最初の市場は東京）／浅草が出てこない
- `STATUS` を `concept` 以外にする

**否定文でも止まります。** 「申し込みは受け付けていません」でも「申し込み」で引っかかります。
語そのものを使わない言い方にしてください。

## 4. 売り始めるとき

いまの規約・プライバシー・事業者情報は、**売っていないことを前提に**書いてあります。
足すのではなく、商品が決まってから書き直してください。

要るもの：

1. 特定商取引法に基づく表記（販売価格・支払方法と時期・提供時期・返品条件・電話番号）
2. 契約としての利用規約（成立・代金・提供時期・解除）
3. 決済クライアント（前の版は git の履歴にあります。`src/lib/stripe.ts` の2026-10-25以前）
4. `concept.ts` の `STATUS` を変える → 止まるので、その時点で売る口の判定を作り直す

---

## 5. 連絡が来たときに

- 宿や自治体の方から、**公開していない情報を含む連絡**が来ることがあります。規約第3条・プライバシー第8条で「第三者に開示しない・検討の範囲を超えて使わない・公開するときは同意を得る」と約束しています。そのとおりに扱ってください
- 連絡の中身を、アクセス解析や外部のツールに入れないでください
- やりとりが終わって検討に要らなくなったメールは削除します（プライバシー第7条）

## 6. 運営者にご確認いただきたいこと

- **名前**：「タシカメ（確かめる）」は相談サービスのための名前でした。旅先での出会いと客室での振り返りを指す名前としてはずれています。付け替えるかどうか
- **英語版**：訪日旅行者が End User なので、いずれ英語の面が要ります。前の /en は相談サービスのものだったので消しました。構想が固まってから
- **市場**：ブリーフの冒頭は「東京で固定」、後半に「京都」の段落がありました。東京（浅草・蔵前）で作ってあります
- **個人情報**：構想が実現すると、写真・位置・行動の記録を預かることになります。いまのプライバシーは「何も預からない」前提です。MVPで1室でも動かす前に、書き直しが要ります
