# Product Brief — Recovery Path（理解 → 行動の SaaS）

> 仮称: Recovery Path（toC）／ Recovery Path for Partners（toB ホワイトラベル）
> 位置づけ: 5年計画 Phase 3〜4 の製品。**いまは作らない**（理由は §6）。

関連: [`BUSINESS_PLAN.md`](./BUSINESS_PLAN.md) ／ [`FIVE_YEAR_PLAN.md`](./FIVE_YEAR_PLAN.md)

---

## 1. 一行

ゲーミフィケーションと図解とシステムで、顧客が悩みを**本質（なぜ起こるか）から理解し、
行動を改善できる**ようにする教育プロダクト。toB（パートナーの顧客教育）にも、
toC（直接）にも SaaS として展開する。

## 2. なぜ作るのか（戦略的意味）

- **堀の製品化**: いまサイトに分散する「感情 → 原因 → 自己観察 → 行動 → 可視化」を、
  1本の使われ続ける体験に束ねる。編集の権威が「読み物」から「ツール」になる。
- **データの自動収集**: 行動と変化の追跡そのものが、**縦断的な改善データ**を生む。
  「改善事例をどう集めるか」の構造的な答え。＝堀を太らせる。
- **認証の実体化**: Recovery Certified の第4原則「顧客教育（決定を急がせない読み物を備える）」
  の実装そのもの。認証パートナーが**院内で使う教育ツール**になる。

## 3. プロダクト構成（4レイヤー）

1. **理解** — 「なぜ起こるのか」をインタラクティブな図解で。territories の原因解説を、
   読む→操作して分かるに変える（メカニズムの可視化）。
2. **自己観察** — Recovery Check を起点に、自分の状態を**地図/ダッシュボード**として可視化。
3. **行動** — 小さな半歩（生活の調整・受診の検討・セルフケア）を、緩やかに記録・伴走。
4. **可視化** — 自分の変化を時間軸で見られる。これが継続動機であり、改善データの源。

## 4. 二つの市場

### toB（B2B2C・最有力の楔）
- 認証パートナー（クリニック/サロン/ジム/専門家）の**顧客教育ツールとしてホワイトラベル提供**。
- パートナーの痛み（強引営業せずに顧客を教育・納得させたい）を直接解決する。
- 現場で**パートナー側の一次データ**が貯まり、データループ（貯める→学ぶ→還す）が太る。
- 収益: SaaS 月額（席数/店舗数）＋ 初期導入・カスタム開発（DX本業と直結）。

### toC（直接）
- フリーミアム/サブスク。理解の基礎は無料、伴走・可視化の深い部分を課金。
- Recoveries Letter・体験パッケージと束ねる（回復体験の OS 化）。

## 5. 「静かなゲーミフィケーション」設計原則（ブランド防御）

このブランドは「通知も煽りもない」。一般的なゲーミフィケーションは矛盾する。採用するのは
**プレッシャーを生まない種類だけ**。

- 採る: 自分の状態が**地図として埋まっていく**可視化／途切れても罰しない緩やかな継続／
  理解が深まる操作体験／内省を促す静かな問い。
- 採らない: ポイント争い・ランキング・連続記録の脅し・恥を煽るバッジ・プッシュ通知。
- 原則: **「見える進捗」は提供する。「感じる圧力」は提供しない。**

## 6. ビルド順序（重要・順序を崩さない）

- **いまは作らない。** Phase 0（一次データ100件）を逸らさない。
- まず**手動・軽量でループを検証**：どの理解が、どの行動を、どれだけ変えるかをデータで掴む。
- 検証で効くと分かった教育・行動だけを、**Phase 3 で systematize** する。
- SaaS は、蓄積した一次理解の**上に**建てる（堀が先、製品が後）。

## 7. 規制・倫理（必須ゲート）

- **薬機法・医療機器**: 診断・治療・健康効果の断定を謳うと医療機器規制に触れる。
  本製品は「**教育・自己理解の支援**」に限定し、診断・受診勧奨をしない（既存の免責と整合）。
- 設計前に専門家レビュー（薬機法・医療広告・景表法・個人情報）を通す。
- **データ倫理**: 縦断データは堀であると同時に、当事者の最も繊細な情報。匿名化徹底、
  PII を分析に出さない、尊厳を最優先。

## 8. 収益（構造・仮説）

| 区分 | 課金 | 立ち上がり |
|---|---|---|
| toB SaaS（ホワイトラベル顧客教育） | 月額（店舗/席数）＋導入 | Phase 3（Y3〜Y4） |
| toB カスタム開発 | 受託 | Phase 3 |
| toC SaaS | フリーミアム/サブスク | Phase 3〜4 |
※ 金額は実データでモデリング。本書では断定しない。
