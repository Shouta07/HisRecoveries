## いまどうなっているか

タシカメは「確かめる 5回パス ¥7,980」を主商品にした、
マッチングアプリ向けの相談サービス。

    確かめる  日常使い      5回パス       ¥7,980            売れる
    決める    必要な時だけ  15分 / 30分   ¥5,980 / ¥9,800   受付前
    試す      勝負どころ    Mock Date     ¥19,800〜         受付前

「受付前」は鍵が揃うと自動で開く（`lib/call/gate.ts`）。
`available` を手で true にするとビルドが落ちる。

取引はここまでつながっている。

    相談 → ケースに紐づけ → 5回パス → 1回消費
    → 女性が自分で取る → 回答 → 返却
    → 残り回数と現在地 → 続きから2回目
    → 集まらなければ回数が戻る

## 守っている決まり（変えるときは理由を書く）

- **AIが女性の感情を作らない。** 印象・判断・評価は人が入れたものだけ。
  AIがやってよいのは、読む・まとめる・整理する・書く。
- **答える女性への約束**（`lib/responder/policy.ts`）は、
  消えるとビルドが落ちる。言いにくい相談は既定で届かない。
- **安さで売らない・怖がらせて売らない**（`scripts/check-copy.mjs`）。
- **買えないものを買えるように見せない。**
- **数え物は Postgres 側で数える。** チケットの増減と案件の取り合いは、
  行を押さえたまま判断する（`spend_pass` / `refund_pass` / `claim_invite`）。
  アプリ側で「読んでから書く」に戻さないこと。
- 値段を変えたら、報酬と上限も一緒に見る（`lib/economics.ts` が落とす）。

## いま取るべき最初の課題

P0 は1つ残っている。

- **パスの鍵が端末から消えると取り戻せない。**
  いまの逃げ道：相談のURLを開くと、その相談に使ったパスの鍵が
  端末に入り直す（`RememberPass`）。だから相談URLを1つでも
  持っていれば戻る。ただし全部消えたら戻せない。
  本当の直し方はメールに鍵を送ること。メール基盤が無いので未着手。

そのあとは P1 の **画像・LINEスクショのアップロード**。
「このLINE送っていい？」がいちばん多い入口なのに、
いまは文字で書き写してもらっている。

Supabase Storage（private bucket ＋ 署名付きURL）が要る。
**別の人のスクショが見える事故だけは、絶対に避けること。**
鍵が無い環境では動作確認ができないので、
書いたら人に確認してもらうまで画面に出さない
（`lib/call/gate.ts` と同じ、鍵が揃ってから開く形にする）。

## 注意

- **本番へマージしない**（main へのマージがそのまま本番デプロイになる）。
  人が起きていて、確認したうえで押すこと。
- LLM の鍵は入っていない。入れると従量課金が発生する。
  いまは AI 無しで成果物が成立する構成にしてある。
- Supabase / Stripe / Daily の鍵も入っていない。
  この環境ではデータベースに触る経路は全部 no-op になる。
- **`supabase/schema.sql` は流し直しが必要。**
  関数が無いと、チケットが減らない・返らない・案件が取れない。
