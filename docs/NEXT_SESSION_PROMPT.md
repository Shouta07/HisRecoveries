## いまどうなっているか

タシカメは「確かめる 5回パス ¥7,980」を主商品にした、
マッチングアプリ向けの相談サービス。

    確かめる  日常使い      5回パス       ¥7,980   売れる
    決める    必要な時だけ  15分 / 30分   ¥5,980 / ¥9,800   受付前
    試す      勝負どころ    Mock Date     ¥19,800〜         受付前

「受付前」は鍵（`DAILY_API_KEY` ほか）が揃うと自動で開く（`lib/call/gate.ts`）。
`available` を手で true にするとビルドが落ちる。

## 守っている決まり（変えるときは理由を書く）

- **AIが女性の感情を作らない。** 印象・判断・評価は人が入れたものだけ。
  AIがやってよいのは、読む・まとめる・整理する・書く。
- **答える女性への約束**（`lib/responder/policy.ts`）は、
  消えるとビルドが落ちる。言いにくい相談は既定で届かない（自分で入れた人だけ）。
- **安さで売らない・怖がらせて売らない**（`scripts/check-copy.mjs` が見張る）。
- **買えないものを買えるように見せない。**
- 値段を変えたら、報酬と上限も一緒に見る（`lib/economics.ts` の判定が落とす）。

## いま取るべき最初の課題

`docs/BACKLOG.md` の P0 が2つ残っている。

1. **返金でチケットを戻す口が無い。**
   画面では「集まらなかった分を戻す」と言っている。
   `pass_uses` を消すのではなく、打ち消す行を足すこと（消すと履歴が消える）。
2. **パスの鍵が端末から消えると取り戻せない。**
   メールに鍵を送る仕組みが要る。

## 注意

- **本番へマージしない**（main へのマージがそのまま本番デプロイになる）。
  人が起きていて、確認したうえで押すこと。
- LLM の鍵は入っていない。入れると従量課金が発生する。
  いまは AI 無しで成果物が成立する構成にしてある。
- Supabase / Stripe の鍵も入っていない。この環境では
  データベースに触る経路は全部 no-op になる。
- `supabase/schema.sql` は流し直しが必要（`spend_pass` が無いとチケットが減らない）。
