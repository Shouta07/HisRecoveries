# 夜のあいだにやったこと

## 1. 今夜やったこと

**P0 を1つ直した。** チケットの二重消費。
`spend()` は残高を読んでから書く2段構えで、同時に来ると両方が
「足りている」と判断していた。5回パスで6回使える瞬間があった。

数える処理を Postgres 側（`spend_pass`）へ移し、行をロックしたまま
数えて書くようにした。同じ相談の二度目も関数の中で止めている
（画面の二度押し・Webhookの再送・リロードは、どれでも来る）。

**P1 を1つ埋めた。** 相手ごとのケース（`relationship_cases`）。
画面では前から「前回の続きから相談できます」と言っていたのに、
相談は1件ずつ独立していて、実際には毎回ゼロから書かせていた。
表・ビュー・作成と紐づけまで作った。

**P2 を1つ。** マイページのいちばん上に残り回数を出した。

    → マイページに残り回数 → 2回目

## 6. Security

- チケットの引き算を行ロックの中に入れた（二重消費の穴を塞いだ）
- `spend_pass` は `security definer`。呼べるのはサービスキーを持つ側だけ
- ケースの呼び名から、連絡先・URL・長い数字を落とすようにした
  （相手はこのサービスに同意していない第三者なので、持たない）

## 7. テスト

- ビルド時の判定（約90か所）／`check-schema` ／ `check-copy` ／
  `tsc --noEmit` ／ `next lint` — すべて通過
- `spend_pass` の6つの要点をSQLの本文で確認
- 呼び名の判定を6通りで確認
- 375 / 390 / 430 / 1280 × 7ページ — 横はみ出し 0、JSエラー 0

## 8. 新たに見つけた問題

- **返金の口が無い。** 「集まらなかった分を戻す」と画面で言っているが、
  使った1回分を戻す処理が無い。`pass_uses` を消すのではなく、
  打ち消す行を足す形にすること（消すと履歴が消える）。
- **パスの鍵が端末から消えると取り戻せない。** メールに鍵を送る仕組みが要る。
