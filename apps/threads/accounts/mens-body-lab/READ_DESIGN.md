# 常に読まれる投稿設計 — Threadsで伸びる型 × His Recoveriesのドメイン

「スクロールを止めさせ、最後まで読ませ、返信させる」ための型。
これは投稿本文の設計指針。trend_analyzer が実データで随時上書きする（下記§4）。

---

## 0. 2026年アルゴリズムの前提（Web調査で裏取り済み・2026-07更新）

- **最重要指標は「返信数×会話の質」**。いいねより、意味のあるやり取りが生まれる投稿が伸びる。
- **滞在時間**も評価対象。読ませる密度が必要（スカスカのポエムは不利）。
- **初速**: 投稿直後の反応でおすすめ露出が決まる。**最初の1時間の返信には必ず返信する**（手動運用ルール）。
- 定石の3段構成=「冒頭フック → 具体的な価値 → 返信を誘う締め」。
- フックの型=「問題提起型 / 数字型 / 逆説型 / 共感型」。質問参加型は反応を生みやすい。
- **リンク付き投稿はリーチが伸びにくい** → 認知・ファン化はリンク無し(type=fan)で回し、
  送客は別の投稿(gift/urgent/areas等)が担う。

## 1. Threadsで伸びる「型」（フォーマット分析）

Threadsは共感と会話で伸びる。広告・教示・煽りは沈む。伸びる型は次の6つ：

| 型 | なぜ止まる/読まれる | 使いどころ |
|---|---|---|
| **セリフ始まり** | 「」で始まると会話が始まった感で目が止まる | 全層のフック |
| **具体的な一場面** | 抽象より「日曜の夜、洗面所で」が刺さる | 共感の入口 |
| **言われた側の記憶** | 「疲れてる？って言われた」等、他者の一言は生々しい | 本人・母 |
| **常識の反転** | 「◯◯だと思ってた。でも違った」= 気づき | insight全般 |
| **淡々とした数字** | 盛らない事実（毎晩2分・1週間）は信頼される | fact |
| **開いた問い** | 最後を問いで閉じると返信が来る（=伸びる信号） | 全連投の最終投 |

**沈む型（禁止）**: 「〇〇な人の特徴3選」等の教示、煽り（必見/神）、効果保証、絵文字多用。

## 2. His Recoveriesのドメイン（何を語るか）

悩み6領域: **薄毛 / 汗・におい / ニキビ・肌 / 顔の印象 / 髭・体毛 / 自意識**
読者3層 + 検索層:

| 層 | 心理の芯 | 刺さる場面 |
|---|---|---|
| ギフト(妻・彼女) | 直したいでなく応援したい | 記念日・写真の彼・誕生日 |
| 母 | 直接言えないが気がかり | 息子が鏡を見ない・就活・写真に写らない |
| 本人・緊急 | 期日が迫り今すぐ | 結婚式前・面接前・日曜の夜の決意 |
| 本人・検索 | 一人で夜に調べる | 「ワキガ 自分で気づく？」等の検索 |

## 3. 掛け合わせ＝読まれるフック設計（1投目の型）

**読まれるかは1投目でほぼ決まる。** 型×場面で、層別に「止まる書き出し」を用意する。

### 公式: 【セリフ or 具体場面】＋【1行の余白】＋【本人には言えない/言わない緊張】

| 層 | 読まれるフック例（1投目） |
|---|---|
| 母 | 「就職してから、息子が写真に写らなくなった。」 |
| 母 | 「息子が、洗面所の鏡をあまり見なくなった気がする。」 |
| 本人(緊急) | 「『このままじゃだめだ』と思う夜は、だいたい日曜に来る。」 |
| 本人(緊急) | 「結婚式まであと3ヶ月。一生残る写真の日が近づいてくる。」 |
| ギフト | 「彼、写真に写るのがちょっと苦手みたい。本人は言わないけど。」 |
| 検索(areas) | 「『ワキガって、自分で気づけるのかな』——その問いだけが消えなかった。」 |

### 連投の骨格（最後まで読ませる）
```
1投目: フック（上の型。2行以内。ここで9割決まる）
2投目: 共感の深掘り or 気づきの反転（「でも」「ただ」）
3投目: 中立な事実 or サービスの静かな紹介（売らない）
4投目: 完全守秘の安心（本人が決める/贈り主にも知らされない）
5投目: CTA（/apply or /areas を1つだけ）
6投目: 開いた問い（返信を誘う＝伸びる信号）
```

### 引用リソース（単発）でも同じ
共感4→気づき4→問題提起3→実績2→誘導1。**1投=1メッセージ**。詩的にせず会話調で。

## 4. データで上書きする（設計→検証→再設計）

- `core/trend_analyzer.py` が**実際に伸びた自分の投稿の構造を分析**し、
  「伸びてる型」を writer のプロンプトに注入する（build_writer_context）。
- 管理ページ「PDCA運用」で**層別・ネタ別の閲覧数×エンゲージ率**を見て、
  勝ちフックを「集中」、負けを「停止」。
- つまり本書は**初期設計**。データが溜まるほど、実際に読まれた型へ自動で寄る。

**運用の合言葉**: 1投目で止める。最後は問いで開く。売らずに守秘で安心させる。
