# 常に読まれる投稿設計 — Threadsで伸びる型 × タシカメのドメイン

「スクロールを止めさせ、最後まで読ませ、返信させる」ための型。
これは投稿本文の設計指針。trend_analyzer が実データで随時上書きする（下記§4）。

旧事業（His Recoveries＝男性ウェルネス。薄毛・汗・ニキビ・顔／ギフト・母・緊急・検索の4読者層）
向けに書かれていた部分を、タシカメの5場面に置き換えた。

---

## 0. 2026年アルゴリズムの前提（Web調査で裏取り済み・2026-07更新）

- **最重要指標は「返信数×会話の質」**。いいねより、意味のあるやり取りが生まれる投稿が伸びる。
- **滞在時間**も評価対象。読ませる密度が必要（スカスカのポエムは不利）。
- **初速**: 投稿直後の反応でおすすめ露出が決まる。**最初の1時間の返信には必ず返信する**（手動運用ルール）。
- 定石の3段構成=「冒頭フック → 具体的な価値 → 返信を誘う締め」。
- フックの型=「問題提起型 / 数字型 / 逆説型 / 共感型」。質問参加型は反応を生みやすい。
- **リンク付き投稿はリーチが伸びにくい** → 問いかけ投稿（週2回）と `no_link: true` の仮説は
  リンク無しで回し、送客は場面別の連投（最終投稿に1本だけ）が担う。

## 1. Threadsで伸びる「型」（フォーマット分析）

Threadsは共感と会話で伸びる。広告・教示・煽りは沈む。伸びる型は次の6つ：

| 型 | なぜ止まる/読まれる | 使いどころ |
|---|---|---|
| **セリフ始まり** | 「」で始まると会話が始まった感で目が止まる | 全場面のフック |
| **具体的な一場面** | 抽象より「平日の夜、入力欄に打ったまま」が刺さる | 共感の入口 |
| **言われた一言** | 「またご飯行こ〜」等、相手の言葉は生々しい | message / signal |
| **常識の反転** | 「◯◯だと思ってた。でも違った」= 気づき | insight全般 |
| **淡々とした数字** | 盛らない事実（10分読み返した・30分たつ）は信頼される | fact |
| **開いた問い** | 最後を問いで閉じると返信が来る（=伸びる信号） | 全連投の最終投 |

**沈む型（禁止）**: 「モテる男の特徴3選」等の教示、煽り（必見/神）、効果保証、絵文字多用、
**女性の反応を創作すること**（「女性はこう思っています」）。

## 2. タシカメのドメイン（何を語るか）

**手が止まる瞬間**を書く。読者は一人。マッチングアプリを使っている20〜30代の男性で、
文面は自分で作れるが、送る直前に「これでいいのか」で止まる人。

5場面（hypotheses.json の slug と同じ）:

| slug | 場面 | 心理の芯 | 出す時間帯 |
|---|---|---|---|
| `message` | 送る前のLINE | 読み返しても自分の目しか無い | 朝 |
| `photo` | 自己紹介文・プロフィール | 書いた本人がいちばん読めない | 朝 |
| `date` | 誘うタイミング | 早いと重い・遅いと冷める | 夜 |
| `signal` | デートのあと | 温度感が自分の記憶からしか分からない | 夜 |
| `distance` | 距離感・言いにくいこと | 友達にも相手にも聞けない | 夜 |

時間帯の出し分けは `persona.posting.slot_type_map`。
朝＝出す前のもの、夜＝会ったあと・誘う前・距離感（夜のほうが手が止まる）。

### 書かないこと（ブランドの線）
- 相手の気持ちを判定しない（脈あり・脈なしは扱わない）
- 効果を保証しない（モテる・落とす・攻略は書かない）
- 読む人を責めない（手が止まるのは慎重さであって、欠点ではない）
- AIや友達に聞くことを否定しない。足りないところだけを書く
- 価格・割引には触れない

## 3. 掛け合わせ＝読まれるフック設計（1投目の型）

**読まれるかは1投目でほぼ決まる。** 型×場面で「止まる書き出し」を用意する。

### 公式: 【具体的な一場面 or セリフ】＋【1行の余白】＋【決めきれない緊張】

| 場面 | 読まれるフック例（1投目） |
|---|---|
| message | 「AIには通した。誤字もない。それでも送信ボタンの前で、一回止まる。」 |
| message | 「打ち終わってから、送信を押すまでが一番長い。」 |
| photo | 「マッチはする。でも、そこから続かない。」 |
| date | 「誘うタイミングだけが、ずっと決まらない。」 |
| signal | 「デートは楽しかった。と思う。」 |
| distance | 「踏み込みたい。でも、踏み込みすぎたくない。」 |

### 連投の骨格（最後まで読ませる）
```
1投目: 止まる瞬間（上の型。2行以内。ここで9割決まる）
2投目: なぜ決まらないか（「でも」「ただ」で反転させる）
3投目: 自分の中には無い情報がある、という気づき
4投目: CTA（/ask を1つだけ。{link} を置く投稿はここだけ）
5投目: 開いた問い（返信を誘う＝伸びる信号）
```

`persona.posting.thread.structure` と同じ流れ。URLは最終CTA投稿に1本だけ
（`url_in_last_only: true`）。

### 問いかけ投稿（週2回・リンク無し）
具体的な場面を1つ出して、**2つに割れる問い**で閉じる（`hypotheses.discovery_questions`）。
どちらが正解かは書かない。割れること自体が、聞く理由になる。

### 引用リソース（単発）でも同じ
共感4→気づき4→問題提起3→実績2→誘導1。**1投=1メッセージ**。詩的にせず会話調で。
仕様は `CONTENT_SOURCES.md`。

## 4. データで上書きする（設計→検証→再設計）

- `core/trend_analyzer.py` が**実際に伸びた自分の投稿の構造を分析**し、
  「伸びてる型」を writer のプロンプトに注入する（build_writer_context）。
- 管理ページ「PDCA運用」で**場面別・ネタ別の閲覧数×エンゲージ率**を見て、
  勝ちフックを「集中」、負けを「停止」。
- つまり本書は**初期設計**。データが溜まるほど、実際に読まれた型へ自動で寄る。

**運用の合言葉**: 1投目で止める。最後は問いで開く。売らずに、片側しか無い材料の話で終える。
