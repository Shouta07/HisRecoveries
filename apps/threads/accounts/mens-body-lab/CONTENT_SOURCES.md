# 引用リソースの型（content_sources.json 仕様）

Threads自動投稿の「素」を貯めるための型。
**1リソース（記事 or 体験メモ）→ 14投稿の在庫**に変換して積む。
システムは在庫を1日1本ずつ順番に消費して投稿する。

- 元にした方法論: 「体験メモ→読者起点の記事設計図（Q1〜Q5）」＋「記事1本→投稿14本 量産手順書」
- 置き場所: `accounts/mens-body-lab/content_sources.json`（管理ページから編集可）

---

## 大原則（全投稿に適用・validatorでも機械チェック）

- 売り込まない。商品名・「ぜひ」「今すぐ」は使わない
- **URLは14本中「誘導(cta)」の1本だけ。** 他の13本はリンクなし・単体で完結した価値を持つ
- 絵文字・感嘆符・煽り語（必見/神/ヤバい）を使わない
- 断定で煽らない。「〜すべき」より「〜かもしれない」「〜だった」
- 1投稿1メッセージ。2つ言いたくなったら2本に分ける
- 主語は読者。「みんな」「男性全般」は禁止。一人に絞る
- **ポエム調にしない**（重要）。体言止めの連発・比喩・過剰な余白（空行）を避け、
  **実際に会話で言う言葉**で書く。「〜、あの感じ。」のような詩的余韻より、
  「うわ、疲れてる」のような素の口語を優先する。

## 配分（1リソース＝14本）

| 分類 | 本数 | 型 |
|---|---|---|
| empathy（共感） | 4 | 読者の場面・感情を助言なしで言い当てて終える。解決策を書かない |
| insight（気づき） | 4 | 「◯◯だと思っていた。でも△△だった。」余白を残す |
| question（問題提起） | 3 | 世の中の当たり前への静かな疑問で締める。誰も批判しない |
| fact（実績・変化） | 2 | 数字か事実だけ淡々と。形容詞で盛らない。「記録の共有」のトーン |
| cta（誘導） | 1 | 核心1行＋「置いておく」＋URL。この1本だけURL可 |

**投稿順序（固定）**: empathy → insight → question → empathy → insight → fact →
empathy → question → insight → empathy → fact → insight → question → **cta（最後）**
= 価値を13本先に置いてから、最後に1本だけ静かに案内する。

## リソース1件のJSONスキーマ

```json
{
  "id": "src-face-tired",
  "kind": "experience",
  "url": "https://hisrecoveries.com/areas/face?utm_source=threads&utm_medium=social&utm_campaign=src-face-tired",
  "reader": {
    "persona": "30歳前後、出張や残業が続く会社員",
    "inner_voice": "疲れてるのが顔に出てるって、自分でもわかる",
    "scene": "出張先のホテル、夜。洗面所の照明で自分の顔を見た直後",
    "search_words": ["顔 疲れ すぐ 治す"]
  },
  "entry_line": "ホテルの洗面所の照明は、今日の疲れを隠してくれない。",
  "min_action": {
    "action": "濡らしたタオルをレンジ40秒で温めて顔に1分乗せる",
    "minutes": 2,
    "tools": "タオルと電子レンジ（なければ熱めの湯）"
  },
  "reframe": "疲れた顔を、放置するものではなく、1分でリセットできるものとして見直す",
  "materials": {
    "empathy": ["投稿本文そのまま ×4"],
    "insight": ["×4"],
    "question": ["×3"],
    "fact": ["×2"],
    "core": "記事全体の核心を1行に要約したもの（ctaの素）"
  },
  "status": "active",
  "used_count": 0
}
```

### フィールドの由来（Q1〜Q5との対応）

| フィールド | 元テンプレ | 中身 |
|---|---|---|
| `reader.persona` / `inner_voice` | Q1 | 誰の・どんな悩みか。一人称のつぶやき |
| `reader.scene` / `search_words` | Q2 | 読みたくなる場面・検索語（GEO質問の素にもなる） |
| `entry_line` | Q3 | 読者の入口の一文（empathy 1本目の素。自分語りで始めない） |
| `min_action` | Q4 | 明日そのまま真似できる最小行動（動詞1つ・5分以内・家にある道具） |
| `reframe` | Q5 | 見方の変化（insight/締めの素） |
| `materials.*` | 手順書STEP1 | 記事から抜いた素材を**完成した投稿本文**として格納 |
| `materials.core` | 手順書STEP1 | 核心1行（cta = core＋「置いておく」＋URL に自動組立） |

### 書式ルール（materials に入れる本文）

- 各本文は**そのまま投稿できる完成形**で書く（140〜200字目安、最大500字）
- 改行で間を作る。1文ごとに詰め込まない
- 素材が記事に無い分類は**創作しない**。本数が足りないままでよい
  （システムは足りないステップを飛ばして次に進む）

## システムの消費のしかた

- `persona.json` の `posting.source_post_ratio`（0〜1）の確率で、
  連投（gift/areas）の代わりに**在庫から単発1本**を投稿する
- 順序は上の固定シーケンス。`used_count` で進捗管理（1リソース=14日ぶん）
- cta の本文は自動組立: `core` ＋「まとめた記事を、ここに置いておく。」＋ `url`
- 在庫が尽きたら自動的に連投（gift/areas）にフォールバック
- すべて `core/validator.py` を通る（煽り語・売り込み・絵文字超過は機械的に弾かれる）

## 運用フロー（リソースの作り方）

1. 体験メモ or /areas 記事を用意する
2. Q1〜Q5テンプレで「読者起点」に変換（このファイル上部の対応表どおり）
3. 手順書STEP1で素材を分解 → 各分類の**完成本文**を書く
4. 管理ページ（設定ファイル編集 → content_sources.json）に1件追加して保存
5. 以降は自動。分析画面で `src:` 始まりの投稿の閲覧数を見て、勝ちリソースの型を横展開
